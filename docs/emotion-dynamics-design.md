## 0. 结论

1. **只有一条心情更新链路**：LLM 给位移档位 → 查表得相对位移 → **置信加权步进**；同时每窗把 `v` 按权重（`W=0.45×conf`）拉向 `anchor_level` 的**绝对档位**（占大头），每 20 窗回补一次 `P`。查表不再直接改状态。
2. **关系是四个慢变量**：`affinity`（好恶）/ `trust`（信任）/ `respect`（尊重）/ `intimacy`（亲近）。各自有基线、半衰期、饱和、负向不对称。
3. **人设决定刻度**：`sensitivity` 决定一次走多远，`reactivity` 决定多容易变，`warmth/trust_speed` 决定好感涨多快，`forgiveness` 决定记仇多久。
4. **衰减不是「掉好感」**：是「不维护就回到基线」。越亲近衰减越慢（投资模型）。
5. **全局心情是独立慢变量**，不由会话均值反推；它只驱动「安静 / 主动」。

## 1. 心情：一条更新链路（步进 + 锚点）

### 1.1 为什么必须只留一套

旧文档有三套（查表、公式、卡尔曼），同一个 `impact=-2` 能算出 -0.30 / -0.12 / 第三个值。
**从 v2 起：查表只产生「相对位移」，步进负责每轮推进，锚点负责周期纠偏。**

### 1.2 三个角色

| 角色 | 谁做 | 产出 |
|---|---|---|
| **观测（相对）** | LLM 判档位 + 代码查表 | `z = clamp(v⁻ + dir×step×sens)`（绝对伪观测）；`z−v⁻` 才是位移 |
| **预测** | 衰减 + 基线 | `v⁻`（如果没发生这件事，她现在会在哪） |
| **步进** | 置信加权 | `v_new`（信多少这次位移） |
| **锚点（绝对）** | **每一窗**的判读（`anchor_level` 必填） | `z_abs`（她「现在」整体在哪档） |

### 1.3 公式（只对 v 生效；a/d 一期只记录）

> **量纲**：下面所有公式在归一化 `v ∈ [-1,+1]` 空间计算；落盘/展示 ×100。
> 若把 `abs(v)=32` 代进 `1−0.6×abs(v)`，会得到 −18.2 → Δ 反向。**先归一化，再算。**

```text
# ① 预测（先衰减）
v⁻ = base_v + (v_prev − base_v) × exp(−Δt / τ)      τ = 半衰期 / ln2
P⁻ = P_prev × exp(−2Δt / τ) + q_rate × Δt_h          q_rate = 0.02 + 0.10×reactivity（每小时）

# ② 观测（LLM 档位 → 数值）
z  = clamp(v⁻ + dir × step(|impact|) × sensitivity, −1, +1)
R  = 0.02 + 0.60 × (1 − confidence)²                 # 置信低 → R 大

# ③ 步进（每轮）
P⁻ = min(P_EVENT_CAP, P⁻ + P_EVENT_BOOST)  若 |impact| ≥ 2   # 突发事件回补（2026-11-26）
K  = P⁻ / (P⁻ + R)                                   # 这次该信几成
Δ  = K × (z − v⁻) × (1 − 0.6×|v⁻|)                 # 饱和：越接近 ±1 越难走
v_new = clamp(v⁻ + Δ, −1, +1)
P_new = max(P_floor, (1 − K) × P⁻)                    # 不确定度下降，但有下限
```

`P_floor = R_BASE × 0.25`（代码 `mood.P_FLOOR`，不是新参数）：
连续判读会让 `P` 指数衰减到 0，`K→0` 之后**新事件再也推不动 v**（情绪冻住）。
留 1/4 观测噪声当底，稳态 `K≈0.2`，单次 `impact=±1` 约走 0.02 —— 和下面「稳态 0.02~0.05」一致；
锚点仍会把 `P` 抬回 0.02 做纠偏。2026-11-25 真机日志发现并修。

其中：

```text
step(1) = 0.10      step(2) = 0.22
sensitivity ∈ [0.6, 1.4]        （人设）
# 不再单独设 max_step（它恒 ≥ step(2)×sensitivity，永不触发）
# 单次实际最大 ≈ 0.22×1.4×K(≤0.93) ≈ 0.28
单次硬上限 0.35（护栏；当前参数下不触发，只在改参数后兜底）
```

> `a/d` 一期**只记录**（衰减 + 展示），不进 `z`/`Δ`：`impact` 只定义效价方向，
> 没有「arousal 档位 → 步长」的映射；硬套 `clamp(−1,1)` 还会越界（a/d ∈ 0~1）。
> 等有了 a/d 标注再开（DESIGN §3.6 G6）。

**突发事件回补 `P`（2026-11-26 用户拍板）**

问题：稳态 `P` 长期贴 `P_floor≈0.005`，`K≈0.04`，`±3` 档的 `Δv` 只有 **0.012** ——
「突发事件」在数值上等于不存在（线上 313 条事件里 0 条 `|dv|≥0.15`，就是这个原因）。

做法：`|impact| ≥ 2` 时 `P⁻ = min(P_EVENT_CAP, P⁻ + P_EVENT_BOOST)`，
`P_EVENT_BOOST=0.05`、`P_EVENT_CAP=0.20`。

| 稳态下 | 改之前 | 改之后 |
|---|---|---|
| `±1` 的 `Δv` | 0.007 | **0.007（不变）** |
| `±2` 的 `Δv` | ≈0.012 | **0.074** |
| `±3` 的 `Δv` | ≈0.012 | **0.135** |

**为什么要 `P_EVENT_CAP`**：连刷 `±3` 时如果 `P` 一路顶到 1，`K→1`，
`Δv` 直接吃满 `HARD_CAP=0.35`，等于「刷三句就换一个人」。
封在 0.20 → `K≤0.63`，`±3` 最多 0.176，仍然推得动，但不会失控。
`±1` 完全不补 —— 日常碎嘴的节奏不变。

### 1.4 直觉（不用记符号）

- **K 大**：这次判读很可信 / 她本来就不确定 → 多走一点；
- **K 小**：判读含糊 / 她状态很稳 → 几乎不动；
- **q_rate 大**：她本来就情绪化（高 reactivity）→ 不确定度恢复快，下次更容易被推动；
- **Δt 长**：隔得越久，不确定度恢复越多（`Q_eff = q_rate × Δt_h`），不是「每次固定加一点」；
- **R 大**：判读模型自己都没把握 → 当没看见。

### 1.5 三个轴的差异

> 半衰期按**场景**分（群 / 私聊），不是按「轴」分；全局只有 `v` 有 6h。
> `d` 只展示，没有任何数值决策用它。200 条标注继续收 `arousal/dominance`。
>
> **现状（2026-11-25 已接线）**：judge 输出 `arousal/dominance ∈ {low,mid,high}` +
> `confidence`；`mood.update_ad()` 按 `a += confidence × 0.4 × (level − a)` 写入，
> 再按各自半衰期回落到基线（a 0.35 / d 0.5）。
> **一期只记录**（衰减 + 状态卡展示），**不进 `z/Δ`，也不进 `chatty/energy`**——
> 进数值决策是二期的事，等 200 条标注验过再说。
>
> ⚠️ **「只记录」≠「不影响行为」**：`a/d` 会进**状态卡**（prompt 里的
> 「唤醒 0.45｜支配 0.30」），模型会据此调语气。`M9/M11` 只证明「`a/d` 不影响 `v`」，
> 不证明「不影响行为」。
>
> 两条轴**故意不同构**：`a` 是绝对档位 EMA（快），`v` 是相对位移 + 每窗绝对锚点权重（稳）。
> 这个差异由 `M9`（a/d 不影响 v）和 `M11`（置信加权）两条断言盯着。

| 轴 | 群 | 私聊 | 全局 | 是否进 `z/Δ` | 说明 |
|---|---|---|---|---|---|
| `v` 效价 | 30min | 2h | 6h | ✅ 进 | 主状态 |
| `a` 唤醒 | 15min | 1h | — | ❌ 不进 | 已接线：judge 档位 + confidence EMA；**只记录** |
| `d` 支配 | 2h | 6h | — | ❌ 不进 | 已接线：同上，只展示 |

### 1.6 锚点：每窗按权重混入（G3 = A+锚点；2026-11-26 加重）

> 相对位移有个天生缺陷：它只会「往这个方向挪」，**纠正不了「v 本来就错了」**。
> 所以判读**每一窗都必须给 `anchor_level`**，代码每窗把 `v` 按权重拉向绝对档位。

**触发**：**每一窗**（`anchor_level` 必填，ADR-042）。
下面两个只决定「什么时候额外回补 `P`」，不决定要不要锚：

```text
① 该会话累计 20 个窗口（mood.observe）  ← 被 relevance<0.25 跳过的窗口**也计数**
② 静默 ≥30 分钟（只在 anchor_tick 定时器里判；observe 内没有这个分支）
```

> ⚠️ 2026-11-26：`observe` 里原来也有「静默 30min」判断，但 `observe` 每窗都会刷新
> `anchor_at`/`updated_at`，只要模型每窗都给 `anchor_level`，这个条件**恒为 False**——
> 是死代码，已删。静默回补现在只有 `anchor_tick` 一条路。

> 为什么跳过的也计数：全是「哈哈」的群永远到不了 20 次真判读；
> 若只数真判读，`P` 会一路衰减到 `K→0`，状态冻结。开关：`MOOD_ANCHOR_COUNT_SKIPPED=1`。

**输入**：judge 只看「她的 THINK + 最近 8 条消息」，**不看当前 v、不看状态卡**（防回声）。

**输出**：`level ∈ {-2,-1,0,+1,+2}` + confidence（和 impact 同档，但语义是「她现在整体在哪」）。
缺这一项 → 记 `ANCHOR_STAT.miss` + INFO，本窗不做锚点（不拿 `desirability` 猜绝对档位）。

**融合**（每窗）：

```text
z_abs = clamp(baseline_v + map(level), −1, +1)
map:  −2→−0.70,  −1→−0.35,  0→0,  +1→+0.35,  +2→+0.70

if |z_abs − v| < 0.15:  跳过（已经在附近，别抖）
W   = 0.45 × confidence                  # MOOD_ANCHOR_WEIGHT
Δ_a = clamp(W × (z_abs − v), −0.20, +0.20)   # 单次最多挪 0.20
v   = v + Δ_a

# P 只在 ①/② 时回补（每窗都补 = P 永不降 = 滤波器失效）
P   = min(1.0, P + 0.02)
```

**为什么 W 这么大**：2026-11-26 用户拍板「`anchor_level` 也占一大部分」。
`impact` 只解释「这一窗又推了多少」，绝对档位才是主项；否则纯相对会一路漂。
单次仍被死区 `0.15` 和 `|Δ_a| ≤ 0.20` 夹住，不会一次拽飞。
`MOOD_ANCHOR_GAIN=0.25` 现在只给**独立锚点**（静默定时器 / 手动 `/测函数`）用。

**边界（很重要）**：`observe()` 返回的 `dv` **不含** `Δ_a`。
- `dv` = 事件步进 → 好感 / 记忆显著性 / 峰值事件只吃它；
- `dv_total = dv + Δ_a` = 这一窗 `v` 的真实变化 → **只做诊断**，不进任何模型。

理由：`Δ_a` 是「对她整体水平的重新估计」，不是「这个人造成了这件事」。
把它算进好感 = 「她今天心情好，顺手记到旁边人头上」，违反唯一原则（ADR-043 / §2.11）。
所以「锚点占大头」只体现在**心情**上，不会让好感跟着跳。

**回声护栏**：`anchor_level` 是主项之后，prompt 里**不再给当前数值**
（原来写「当前心情 +0.35」）——否则模型最省力的答案就是照抄，ADR-029 警告的「纯绝对会回声」
会立刻发生。现在只给上一轮那个词。

**它和 `impact` 不是重复计分**：`impact` 是「这一段让她往哪走」（导数），锚点是「她现在整体在哪」（水平）。同一批消息确实会被看两次，但一次用于增量、一次用于纠偏，语义不同。

> ⚠️ 所以**不要**给锚点加 `msg_ids` 去重。去掉看过的消息，锚点就退化成第二个步进，
> 再也纠不了「`v` 本来就错了」——这正是它存在的唯一理由。
> 约束它的是死区 `0.15` 和单次 `|Δ_a| ≤ 0.20`，不是去重。

**它纠的是「漂移」，不是「偏差」**：如果 judge 系统性把「调侃」读成负面，
每窗 `impact` 往下推、20 窗后锚点用同一副眼镜再确认一次——锚点会把偏差当成事实。
这是「锚点不看当前 `v`」的代价：避免了回声，也失去了唯一的状态对照。
**偏差只能靠 200 条标注校准（P6），不能靠锚点。**

**审计**：`mood_audit` 记 `{"kind":"anchor","level":…,"z_abs":…,"v_before":…,"v_after":…,"K_a":…}`。

**验收**：单次 `|Δv| ≤ 0.2`（由 clamp 保证，不是靠 K_a 小）；死区 `0.15` 防抖。**不设「累计解锁」**——每次都被 clamp 自然限制，不额外放开累计。

## 2. 人设量化：从「性格」到「参数」

### 2.1 六个参数

| 参数 | 范围 | 作用 | 不作用 |
|---|---|---|---|
| `sensitivity` | 0.6~1.4 | 乘在观测步长上（一次走多远） | 不影响衰减 |
| `reactivity` | 0~1 | 过程噪声 Q（多容易变） | 不影响单次幅度 |
| `warmth` | 0~1 | 好感增长系数 `k` | 不影响心情 |
| `trust_speed` | 0~1 | 好感增长速度（自来熟） | 不影响信任上限 |
| `forgiveness` | 0~1 | 负面权重、记仇时长 | 不影响正面 |
| `expressiveness` | 0~1 | **只影响语气** | 不影响任何数值 |
| `baseline_v` | -0.3~0.3 | 心情回落点 | — |

### 2.2 两条落地路径

**路径 A（推荐）：人格卡直接写 6 个数**，作者可控、可解释。

**路径 B：从 Big Five 映射**（没有现成数值时用）：

```text
N=神经质 E=外向 A=宜人 （都归一化到 0~1）

sensitivity  = 0.6 + 0.8×N
reactivity   = N
warmth       = 0.5×(E + A)
trust_speed  = 0.5×(E + A)
forgiveness  = A × (1 − 0.3×N)
expressiveness = E
baseline_v   = clamp(−0.1 + 0.2×(E − N), −0.3, 0.3)
```

> 哲学依据：Aristotle 的 `hexis`（习性）——性格是**稳定的倾向**，不是当下情绪。
> 所以它应该进「参数」，而不是每轮让模型自由发挥。

### 2.3 人设 → 单次步长（回答「单次幅度怎么由人设决定」）

```text
单次实际最大 Δ = step(2) × sensitivity × K_max
              = 0.22 × sensitivity × 0.93
```

| 人设 | sensitivity | 单次最大 Δ |
|---|---|---|
| 冷漠钝感 | 0.6 | ≈0.12 |
| 普通 | 1.0 | ≈0.20 |
| 敏感易炸 | 1.4 | ≈0.29 |

再叠加 `saturation`：`Δ × (1 − 0.6×|v|)`，越接近 ±1 越难走。

> 旧版另设 `max_step = 0.10 + 0.15×sensitivity`，它恒 ≥ `step(2)×sensitivity`，
> 永不触发，已删（G5）。0.35 只作改参数后的兜底护栏。

## 3. 关系：四个慢变量

### 3.1 为什么不是一个标量

| 量 | 回答的问题 | 变化速度 |
|---|---|---|
| `affinity` | 我**喜不喜欢**这个人 | 天 |
| `trust` | 我**信不信**这个人（会不会伤害我/靠不靠得住） | 周~月 |
| `respect` | 我**看不看得起**这个人（能力/品格） | 月 |
| `intimacy` | 我们**熟不熟**（相处量） | 周 |

哲学对应：Ryle 的 `occurrent`（心情，此刻）vs `dispositional`（关系，倾向）；
Abhidharma 的 `vedanā`（受，当下）vs `anuśaya`（随眠，潜在倾向）。

### 3.1b 亲近度 intimacy 的更新（补 G2）

`intimacy` 不是好感，是「相处量 + 自我披露」；**不联系会变淡（30 天半衰期）**；负面事件降的是 affinity/trust，不直接降 intimacy。

> **2026-11-25 修正（as-built）**：`intimacy = score/(score+3)`（饱和曲线），不是 `score/3`。
> 旧口径是线性的，20 条相处记录就顶到 1.00（实测 240 人里 7 个 1.00），
> 而 1.00 会把 affinity 的衰减 τ 拉到最大。现在 score=3→0.5、6→0.67、12→0.8，只逼近 1。

```text
Δintimacy = 0.03 × (1 − intimacy) × depth
depth = 0    普通接话 / 打招呼
depth = 0.5  连续对话 ≥5 轮 / 私聊 / 共同完成一件事
depth = 1.0  自我披露（说自己的事）、被安慰、一起扛过负面事件

衰减：intimacy_t = intimacy × exp(−Δt / 30天)
范围：clamp(0, 1)
```

> 它驱动 `τ_aff`、关系阶段、proactive 的 warm 乘数——没有更新式，这三个模块会一起冻住。
>
> **实现口径（2026-11-25 定）**：`intimacy` 以 `DESIGN §3.2` 的**派生量**为准
> （由 `bond notes` 的条数/情绪/时间 + affinity 贡献算）。上面这个 `Δintimacy` 是
> **写 notes 时的权重建议**，不是第二个状态变量；**不要两者同时累加**。

### 3.2 好感更新（含人设与防刷）

```text
Δaff_raw = |Δv| × k × trust_speed_factor × relation_relevance × novelty_aff

k                  = 0.04 + 0.12 × warmth
trust_speed_factor = 0.6 + 0.8 × trust_speed
novelty_aff        = 1 / (1 + 0.6×n_aff)        # 同人 30min 内第 n 次
relation_relevance ∈ [0, 1]   # judge 可连续；标注用 0/0.5/1 三档；world/self 为 0，缺省 0.5

正面：Δaff = +Δaff_raw
负面：Δaff = −Δaff_raw × (1.3 − 0.6×aff)   # 越喜欢越宽容；越讨厌越敏感

饱和：Δaff ×= (1 − |aff|)
单次对称上限：Δaff ∈ [−0.10, +0.10]
每日上限：|ΣΔaff/day| ≤ 0.15
```

> **2026-11-26 修正（v2.5）**：档位扩到 **7 档**——`0.10`（±1）/ `0.22`（±2）/ `0.40`（±3）；
> 判读报 `desirability(-3~+3) × cared(0/1/2)`，代码合成 `impact`。
> **好感 v2（`AFF_MODEL=v2`）改用实际位移 `Δv_actual` + 三段式**，
> 完整公式见 [affinity-quantification-design.md](affinity-quantification-design.md)；
> 下面这段只描述 **v1（默认线上）**。
>
> **2026-11-25 修正（v1 as-built）**：`|Δv|` 是 `0.10`（±1）/ `0.22`（±2）；
> 旧实现把结果夹成 `[−0.06, +0.08]`（跌得比涨少 25%），且负向权重误传了「心情值」
> 而不是「好感」，等于惩罚在惩罚。v1 现在：
>
> - 涨跌**同一套步长**，对称夹 `±0.10`；
> - 负向乘 `neg_weight(当前好感)` = `clamp(1.3 − 0.6×aff, 0.5, 2.0)`；
> - `novelty_aff = 1/(1+0.6×n_30min)`：同一个人 30 分钟内第 n 次，防连着刷；
> - 道歉（`repair`）只把**这次负向减半**，不强行变成加分。
>
> 线上实证（2026-11-25 20:36）：`Δ+0.10/speaker` → `好感 +0.010 → +0.02`；
> 负向同样会掉（历史 `affinity_log` 265 条里 108 条为负）。
>
> **v1 用「事件强度」，v2 用「实际位移」**（2026-11-26 分叉）：
>
> ```text
> Δv_event  = 档位换算的 ±0.10 / ±0.22 / ±0.40   ← v1 好感 / 记忆刻痕 / 群心情
> Δv_actual = observe 真正走出来的 dv（≤0.35）    ← v2 好感 / mood_events / 日志审计
> ```
>
> v1 的理由：好感衡量「这件事有多重」；群心情的 0.4 / 0.7 阈值按 ±0.20 单条上限校准。
> **v2 反过来**：好感 = 寄存在每个人那里的心情涨落历史，必须用 `dv_actual`
> （`dv` 里已含 K / 置信 / 人设，不能再乘一遍）。
> v1 额外乘 `0.5 + 0.5×K`；v2 不乘。

**验证「冷漠 0.28 → 0.014」**（|Δv| 取当前可达上限 0.28；n=0 → novelty=1；aff≈0 → saturation≈1；relation_relevance=1）：

```text
warmth=0.2, trust_speed=0.2, |Δv|=0.28
k=0.064, factor=0.76
Δaff = 0.28×0.064×0.76 ≈ 0.0136 ≈ 0.014  ✅

热情 warmth=0.8, trust_speed=0.8：
k=0.136, factor=1.24
Δaff ≈ 0.047（约 3.5 倍）
```

### 3.3 好感衰减：回到基线，不是「扣分」

```text
aff_t = base_aff + (aff_{t−1} − base_aff) × exp(−Δt / τ_aff)

τ_aff = 7天 × (1 + 2×intimacy) × (1 + 0.5×contact_norm)
contact_norm = min(1, 近7天互动次数 / 50)
```

含义：

- **越亲近，掉得越慢**（Rusbult 投资模型：投入越多，越不会因为一次不快就归零）；
- **越常联系，掉得越慢**（Zajonc 单纯曝光效应：熟悉本身维持好感）；
- 长期不联系 → 慢慢回到「陌生人基线」，而不是变成负数。

### 3.4 信任：涨得慢、掉得快、修得更慢

```text
正向（守约/帮忙/说真话）：
  Δtrust = +0.08 × (1 − trust) × (1 − grudge)

失信（骗/放鸽子/背后说坏话）：
  Δtrust = −0.25 × (1 − trust)      # 越信任，绝对跌幅越大（背叛更痛）

衰减：
  trust_t = 0.20 + (trust − 0.20) × exp(−Δt / 45天)
```

### 3.5 尊重：只由「能力/地位」信号改

```text
能力信号（解决问题/被认可）：
  Δrespect = +0.05 × (1 − respect)

无能信号（当众出丑/被否定）：
  Δrespect = −0.10 × (1 − respect)     # 负面权重 2 倍（ negativity bias ）

衰减：
  respect_t = 0.30 + (respect − 0.30) × exp(−Δt / 90天)
```

### 3.6 记仇与修复（Gottman 的 repair）

```text
grudge ∈ [0,1]，半衰期 14 天
负面事件：grudge += 0.30 × (1 − grudge) × severity
道歉/补偿：grudge ×= 0.5
连续 3 次正向：grudge −= 0.10
```

`grudge` 不进 prompt 数字，只用于：
- 降低信任恢复速度；
- 决定「要不要提旧事」；
- 决定语气（更短、更冷）。

### 3.7 关系阶段（社会渗透理论）

| 阶段 | 条件 | 行为影响 |
|---|---|---|
| 陌生 | `intimacy<0.2` | 客气、不主动开玩笑 |
| 认识 | `0.2~0.45` | 可以接梗，不深聊 |
| 朋友 | `0.45~0.7` | 主动关心、可吐槽 |
| 亲近 | `>0.7` | 撒娇/抱怨/找倾诉 |

**可以降级**（depenetration）：长期无互动 + 信任下降 → 回到上一阶段。

## 4. 全局心情与「安静 / 主动」

### 4.1 全局心情是独立慢变量

```text
每个 impact 同时更新会话状态和全局状态：
  v_global ← 步进(v_global, z, Q_global, R)   τ=6h   # 锚点同样作用于全局
```

**不再用「会话均值」反推**（旧版循环定义）。

### 4.2 输入定义（每个都能算）

| 变量 | 定义 |
|---|---|
| `arousal` | 各会话 `a` 的加权均值（按最近活跃度）；`a` 由 judge 档位平滑写入 |
| `recent_negative_ratio` | 近 2h 负面 impact 数 / 总 impact 数 |
| `group_tension` | 近 30min 群内「人对人」消息的负向情绪比例（来自 interaction_edges.sentiment） |
| `recent_positive` | 近 2h 正面 impact 数 / 5，截断到 1 |
| `energy` | `max(0, v_global) × (0.5 + 0.5×arousal)`；**二期**：`a` 接进决策后才启用 |
| `loneliness` | `min(1, 距上次**任意**互动的小时数 / 12)`；群按「上次被 @ / 被点名」，私聊按最后一条消息 |
| `recent_rejection` | 近 2h **她主动发起**（主动私聊 / 群接话）后 10min 内没得到回应的比例；**她选择安静不算被拒绝** |

### 4.3 两个倾向分

```text
quiet = sigmoid(
    1.6×(0.2 − v_global) + 0.6×recent_negative_ratio
  + 0.4×group_tension − 0.5×recent_positive
)
# 注意：quiet 里**不放 arousal**——否则「激动」会同时抬高 quiet 和 chatty，方向相反

# 一期：a 不进决策，所以没有 energy 项
proactive = sigmoid(
    1.4×v_global + 0.5×loneliness − 1.0×recent_rejection
)
# 二期：a 接进 energy 后，再加 + 0.6×energy
```

> 一期如果把 `energy` 留着，`arousal` 恒为基线 0.35 →
> `energy = 0.675×max(0,v)`，与 `1.4×v_global` 共线，等于给正向心情偷偷加 29% 权重。
> 所以一期**显式去掉**，二期再按上面的公式加回来。

决策：**按概率抽样 + 冷却**，不是硬阈值。

```text
if random() < quiet and now > quiet_cooldown:
    少说/短句；但被 @ / 被直接问仍然要回（不装死）
if random() < proactive and now > proactive_cooldown:
    找 trust 最高且最近没拒绝过她的人，私聊低压话题
```

**安静要落成状态，不是只影响语气**（旧 `chat_switch` 的做法，保留）：

```text
chat_switch.quiet(scope, until, reason, by_qq)
  scope = group:<gid> / person:<gid>:<qq>
真不回落在 API 层：tool_choice={"type":"function","function":{"name":"stay_silent"}}
安静时照常读（上下文/现场/记忆/心情都更新），只是不回。
破冰：检测道歉/哄人（对不起/抱歉/我错了/别生气/原谅/和好）
  → 只解除「因这个人而起」的安静；主人道歉一律给台阶。
```

**per-person 粒度**（旧设计，v2 补回）：可以只不理某个人，他的 @ 和图片也不接；
全局 quiet 倾向分只决定「想不想说」，per-person 是「对谁不说」。

恢复：被温柔接住 / 道歉（×1.5）/ 正面事件 → quiet 下降；
连续被冷落 → 安静时长指数退避（10min → 30min → 2h）。

## 5. 判读：窗口、输出、时机

### 5.1 窗口

**判读单位是「窗口」，投递单位是「段」——两者别混。**

```text
段：群聊攒到「安静 3.5s」或 30s / 40 条就关闭，是**投递**单位
窗口：8 条 或 5min（MOOD_WINDOW_MAX_SEC），是**判读**单位

段关闭后，把段内**未判读**的消息按时间切成 8 条一窗，逐窗判读；
msg_ids 去重跨段生效；单段最多 5 窗（40/8），某窗超时/失败只跳过该窗，不阻塞回复。
```

> 为什么要切：一个 40 条的爆点只判最后 8 条，前 32 条的情绪冲击会**静默丢失**；
> 而慢群 8 句可能跨小时，没有 5min 上限的话，她的状态会一直停在「上一条消息之前」。
> 断言：`P4`（段内 `msg_ids` 并集 == 段内全集）。
>
> **预算不够时**（`MOOD_JUDGE_MAX_PER_HOUR` 触顶）：丢掉最早的窗、只判最近几窗
> （最后一窗必留），并打日志。此时 `P4` 不成立——它是「预算充足」下的断言。
>
> **2026-11-25 修正**：前面的窗口（她没有回复、没有 `THINK`）**不再写心情**，
> 只记录覆盖情况。心情只在她自己回应过的窗口里更新——没有她的心理活动，就没有依据。

#### 5.1b 节流不能把 THINK 丢掉（2026-11-26 用户实测）

用户原话：「我发现她其实**每一句都有写心理活动**的，所以并不是心理活动素材没有，
而是 **cd 给隔离了**。」

线上表现（旧代码）：6 小时内 `无 THINK → 跳过判读` 94 次、`她没写 THINK，Xs 后再看` 54 次，
真正写了好感的只有 **14** 次。看着像「她不写 THINK」，其实是链路丢的：

| 丢法 | 原因 |
|---|---|
| ① 节流丢 | `MIN_INTERVAL=60s` 内又来一条回复 → 直接 `return`，这条 THINK 没了；下一窗她没再说话 → `wrote=False` → 整窗不判 |
| ② 预算丢 | `MOOD_JUDGE_MAX_PER_HOUR` 触顶 → 同样直接 return |
| ③ 调用方没传 | 有的路径只把 THINK 落盘（`data/mood_think.json`），没作为 `think=` 传进来 |

**修法（不动 8 句一窗、不动 60s 节流）**：

1. 节流 / 预算用完时，把这条 THINK 推进 `_PENDING_THINK[key]`（上限 8 条，超过丢最老的）；
2. 下一次真判读时把队列**合并**进 `think`（`"；".join(队列 + 本次)`），判完清空；
   10 分钟以上的旧队列直接丢（不能拿十分钟前的心情算这一窗）；
3. `wrote` 为假时，再兜一层：取 `data/mood_think.json` 里 **`at > 上次判读时间`** 的
   新 THINK（最多 3 条、不含 `auto` 猜测），避免同一条被判两次。

这样「每条 THINK 都会被至少一次判读消费」，判读次数不变（成本不涨），
只是不再白丢素材。`/测函数 心情` 会显示「攒着的 THINK：N 条」。

> **为什么不改成「有 THINK 就立刻判」**：用户明确要「避免 cd 过长」。
> 60s 节流是成本闸门，去掉会让连发几句就判几次。攒队列是「不丢素材 + 不涨次数」。

>        other_name（可选，cause=other 时写第三个人的显示名）

>
> `other_name` 由 `group_scene` 的现场名册解析成 QQ；**解析失败就不动好感/信任**
> （宁可不动，也不要把「C 骂她」记到 A 头上）。`trust/respect` 也记到 `target_qq`

>
> 旧版只有 `speaker/recipient/world`，会把「第三个人骂她」记成 `world`，好感不动（ADR-021）。

## 6. 记忆显著性（拆双强度）

> **记录 ≠ 门槛（ADR-024）**：记忆每个 turn 都记（MEMO / 事件 / fact 都写）；
> `|ΔVAD|` 只决定 `storage`（加粗/显著性）和检索权重，**不决定「记不记」**。
> sqlite 化改的是**检索**（时间 × 情绪双维融合），不是**记录语义**。

```text
u = |ΔVAD| 模长（0~1）

# 倒 U：小冲击几乎不记；中等冲击最显著；极端冲击回落到 0.6（防止一次大事把记忆钉死）
w = 0.3×u                                u < 0.15        # 0 → 0.045
w = 0.045 + 2.1×(u − 0.15)               0.15 ≤ u ≤ 0.60 # 0.045 → 0.99
w = 1.0 − (u − 0.60)                     0.60 < u ≤ 1.0  # 0.99 → 0.60

storage   = clamp(0.15 + 0.45w + 0.20×unexpected + 0.20×relation_relevance, 0, 1)
storage  *= 1.15 if valence < 0          # 坏比好强
retrieval = storage                       # 初始相同

每次被检索命中：retrieval += 0.10 × (1 − retrieval)
时间衰减：     retrieval *= exp(−Δt / τ_kind)      # τ 以「天」计
```

**`τ_kind`（提取半衰期，天）**：

| kind | τ | 理由 |
|---|---|---|
| `event` | 30 | 事件最先淡（和本地 30 天迁移对齐） |
| `bond` | 90 | 相处印象要留得久 |
| `fact` | 365 | 事实基本不忘 |
| `preference` | 180 | 口味会变，但比事件慢 |
| `impression` | 180 | 她对这个人的印象（MEMO 默认 kind）。**2026-11-26 补**：以前漏登记，掉到 `TAU_DEFAULT=30`，和一次性事件同寿命 |
| `style` | 365 | 说话方式最稳定 |

> ✅ 已实现（2026-11-25）：`w` 的 0.045 / 2.1 / 0.6 与 `τ_kind` 的 5 个值
> 已收进 `core/tuning.py` 的 `MEM_*`；`memdb.salience_weight()` / `tau_days()`
> 同时服务 sqlite 与 json 两个后端。
> 数字仍是设计值，等 P6 的 200 条标注跑完再校准——**先有形状，再有数字**。

| 字段 | 含义 | 衰减 |
|---|---|---|
| `storage_strength` | 编码多牢 | **不衰减** |
| `retrieval_strength` | 现在能不能想起 | 衰减、被用变强 |

哲学/认知依据：Bjork「新失用论」——存储强度≠提取强度；
Ebbinghaus 遗忘曲线只管提取。

| E1 | judge 输出 impact/confidence/target/unexpected/relation_relevance | 同事件两次判读档位一致率 >80% |
| E2 | 步进 + 锚点 + 快速通道 + `mood_audit` | 「刚被骂完还在笑」消失；审计可回放 |

## 10. 明确不做

- 不做真实事件生命周期（起止/因果链）；
- 不让 LLM 报连续 VAD 小数；
- 不把「心理活动」当每轮必经；
- 不用单一标量表示关系；
- 不为了「像人」而随机改数值（随机只用于**决策**，不用于状态）。
