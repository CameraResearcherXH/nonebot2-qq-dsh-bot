# 回复流水线（回复类消息）· 逐块对照表

> 代码：`services/reply_pipeline.py`
> 入口：`plugins/chat/__init__.py` → 第 3.5 步 `reply_pipeline.build(...)`
> 注入：`services/llm.py` → `call_llm(staged_text=...)`，放在**最后一条 system**（recency 最高）
>
> 一句话：**固定区只给「人设卡 + 工具 + 标签处理后的上下文」；要回的那句再按需取数。**

---

## 0. 固定拿到的（每轮都有，不随消息变）

| 块 | 里面是什么 | 来源 |
|---|---|---|
| **人设卡** | 你是谁（含外貌）· 性格 | `services/Personality/<人格>.txt` 原文 |
| **工具** | 工具定义 + 工具协议（菜单/长度/表情/记忆/心里话/心情/人称/QQ 操作） | `llm._behaviour_protocol` + `TOOLS_SPEC` |
| **标签上下文** | `时间 名字: 内容` / `这是你之前的回复：内容` / `⭐`（在叫她） | `group_scene.history_lines` |

固定区**不再**放：心情、好感、记忆目录、图书馆、白月光、人物档案全文。
这些全部走下面的动态取数，只给「这一句」相关的。

## 1. 动态取数：8 步，每步一个块

| 顺序 | 块标题（≤30 字） | 取什么 | 拿不到时 | 代码 |
|---|---|---|---|---|
| ① | `▍称呼｜固定区已给，这里再钉一句` | 她叫他什么 / 他叫她什么 | 跳过 | `callname.render` |
| ② | `▍状态｜心情值 · 当前状态 · 那件事的心理` | 心情词+数值 / 刚才那下 / 心里话 / 峰值事件+当时心理 / 群聊总结 / 对他的好感走势 | 退回「心情值 ±N」一行 | `mood.status_block` |
| ③ | `▍档案｜称呼 · 身份 · 好感 · 印象最深的事` | 你叫他 / 他是谁 / 性格 / 相处备注 / 好感词 / 印象最深的一件事 / **他的白月光是谁** | 跳过 | `profiles` + `memory_v2` + `white_moon.profile_note` |
| ④ | `▍总结｜判读模型：这句在接哪句、到底在说什么` | 判读 LLM 结合**最近 10 条上下文**对「要回的这一句」做事实摘要；数字/单位按字面保留 | 用原话当检索词 | `mood_judge.summarize` |
| ⑤ | `▍记忆｜按这句话检索到的旧事` | 用④的总结查本地记忆（最多 4 条） | 记 `0` | `memory_v2.recall` |
| ⑥ | `▍图书馆｜久远归档，人称仅供参考` | 查算力机 RAG（最多 3 条）；**在④之前就并行发起**，只对「像在问事」的消息查（问号/记得/上次/谁/什么/怎么…），同一问题 10 分钟缓存 | 记 `0` | `agent_client.recall` |
| ⑦ | `▍已回｜这条回过没有，别回第二遍` | 当前消息 id 是否在已回集合里 | 视为没回过 | `seg_mids ∩ replied_mids` |
| ⑧ | `▍白月光｜借他习惯的说话方式，不做他` | 「这个人的白月光」的风格摘要 + 2~3 句原话；自定义风格已特批时直接用上传样本 | 记原因（分不够/没样本/关） | `white_moon.render_style_only` |

> ⑤ 和 ⑥ **并行**跑，互不等待；总预算 `PIPELINE_BUDGET=7s`，到点带着已拿到的走。

## 3. 怎么确认「到底有没有调用到」

| 命令 | 看什么 |
|---|---|
| `/测函数 流水线` | 每一步平均耗时 + **上一次每一步的状态**：`✓` / 数字 / `0` / `—(分不够)` / `×异常名`；加「全」打印完整块 |
| `/看模板 流水线 [@人/QQ]` | **只打印流水线**（`▍PIPELINE｜…` + 8 个块），不混人格/规矩/历史；带人时按那个人最近一句话**现跑一遍**（排查“这个人的档案为什么不对”） |
| `/测函数 模板` | 这一轮真正发给模型的所有块（顺序就是真实顺序） |
| `/测函数 链路` | 上一次请求塞了哪些块 / 哪些工具 |
| 日志 `[PIPE]` | `xx.xs｜拉了 称呼,状态,档案,…｜N 字` |

> 状态含义：
> `✓` 拿到了；`0` 查了但没结果；`—` 没数据/不需要；`—(分不够)` 白月光互动分没到 `WHITE_MOON_MIN_SCORE`；`×Xxx` 这一步抛异常（只丢这一步，不影响回复）。

## 4. 白月光到底写在哪

| 位置 | 内容 | 函数 |
|---|---|---|
| **档案块**（③） | 白月光**是谁** + 分数 + 风格摘要；自定义风格已特批时优先 | `white_moon.profile_note` |
| **白月光块**（⑧） | 怎么**借**他的句式（摘要 + 2~3 句原话），不重复「是谁」 | `white_moon.render_style_only` |
| 静态路径（没走流水线时） | `relation_block` 里也会带 `profile_note` | `profiles.relation_block` |
| 长期语料 | 每个人的原话（省流模式也记） | `services/style_vault.py` |

> 所以「档案里没有白月光」这个问题已经修掉：只要互动分 ≥ `WHITE_MOON_MIN_SCORE`（默认 3），
> 档案块就会出现「他的白月光：……」。分不够时不会硬编，`/测函数 流水线` 会显示 `—(分不够)`。

## 5. 人设卡为什么只剩两节

用户 2026-11-24：
> 「人设卡只需要保留简单的你是谁合并外貌，留下说话案例和性格。
>  其他的说话风格、分辨消息等，我们这套系统自己就长出来了。」
>

现在 `小鲸鱼proplus.txt` 只有两节（「你是谁」和「外貌」合并成第一节）：

1. **你是谁（含外貌）**
2. **性格**

> 底线（不碰政治/敏感、不越界、不装懂）已从人设卡移出，
> 放进固定区的 `▍09 别学坏`（`llm._NO_SWEAR`），不占人设卡篇幅。

原完整卡备份在 `services/Personality/小鲸鱼proplus.txt.bak`（`.bak` 不会被 `*.txt` 扫描到）。

不再在人设卡里写第二遍。

## 6. 某一块没出现，先查这里

| 现象 | 最可能的原因 | 处理 |
|---|---|---|
| 没有 `▍状态` | `mood.status_block` 抛异常（会被兜底成一行「心情值 +0」） | `/测函数 流水线` 看是否 `×Xxx`；`/测函数 心情` 看数据 |
| 没有 `▍档案` | 对方还没建档（`profiles.get_profile` 为空且没有称呼） | 让他说一句话，档案会自动 upsert；或 `/测函数 档案 QQ号` |
| 没有 `▍总结` | 判读 LLM 超时（`min(6s, 剩余预算)`） | 看日志 `[PIPE] 总结`；预算可调 `PIPELINE_BUDGET` |
| 没有 `▍记忆` | 总结/原话没命中，且没有可兜底的「关于这个人最近的事」 | `/测函数 记忆` 看召回率 |
| 没有 `▍图书馆` | 这条不是问事（门控跳过）/ RAG 没命中 / 没连上 | `/测函数 图书馆 <问题>` 直接实测；`/测函数 记忆` 看状态 |
| 没有 `▍白月光` | 互动分 < 3 / 样本不足 5 条 / `WHITE_MOON_MODE=false` | `/测函数 白月光 群号` |
| 总结把「192」理解成「192 关」 | ④ 只喂了当前一句、没带上文 | 已在 `mood_judge.summarize` 里带最近 10 条，并硬性要求数字/单位按字面保留 |

## 7. 预算与降级

- `PIPELINE_BUDGET`（默认 `16.0` 秒）：总预算，超时就不等了；用户 2026-11-24
  要求「一定要完整去调一遍」，7s → 12s → 16s（图书馆 RAG 实测 5~14s）；
- `AGENT_LIBRARY_TIMEOUT`（默认 `14.0` 秒）：图书馆单次检索上限；以前写死 2.5s
  导致所有检索都超时、图书馆永远 0 条；
- 每一步独立 `try/except`：失败只丢自己，回复照常；
- 记忆 / 图书馆并行（`asyncio.gather`）；
- 有流水线时，`llm.py` **不再**重复注入静态的 `relation` / `mood` / `library` / `memory_index` / 白月光，
  避免同一件事在一份 prompt 里出现两遍。

## 8. 固定区规矩：行为规则删掉，只留协议（2026-11-24 最终版）

用户最终定稿：
> 「行为规矩基本可以删，硬逻辑 + 心情/好感 + pipeline 已经在管。
>  真正不能删的是协议——MEMO/THINK/MOOD/CALL/表情/NapCat 是数据接口，不是规矩。」

压缩前后（容器实测）：

| 节 | 前 | 后 | 说明 |
|---|---:|---:|---|

| 01 长度 | 163 | 41 | 一句：N 字内直接发，超过转合并转发 |
| 02 接话 | 1024 | 67 | ⭐/@/戳 → 接；其他随心情；(不想回复) |
| 03 查 | 979 | 75 | 不懂 `[[SEARCH]]`、往事 `[[MEMORY]]`、查不到别编 |
| 04 叫人 | 175 | 49 | `[[AT|名字]]`；不确定 `[[WHO|名字]]` |
| 05 称呼 | 424 | 153 | `[[CALL]]` 语法 + target/del |
| 06 记忆 | 683 | 123 | `[[MEMO]]` 语法 + 最多 2 条 |
| 06b 心里话 | 361 | 100 | `[[THINK]]` 每条必写 |
| 06c 心情 | 308 | 51 | `[[MOOD]]` 想说就写 |
| 08 表情 | 644 | 109 | `<sticker:标签>` + 频率/点名 |
| 09 底线 | 302 | 52 | 不骂人/不带死字/不碰政治黄腔 |
| 10 人称 | 423 | 87 | 「我」=他；「你」不一定是你 |
| 11 QQ 操作 | 809 | 191 | 点赞/戳一戳 + 按需 `napcat_help` |
| **合计** | **8398** | **1429** | **-83%** |
| post_rules | 1010 | 202 | 只留：语气/只回当前/引用/链接/多条@/称呼/THINK |

**整节删除**：02b 沟通、02c 接不上、02d 注意力、07 关注谁。
它们分别由以下机制接管：
- 不替别人说话 / 只回当前 → `post_rules` + pipeline 的「这一条消息的人称」；
- 接不上 → 历史块自带 `[[[HISTORY|20]]]` 提示 + pipeline 的记忆/档案；
- 注意力 → 硬逻辑（⭐ / 收件人）+ 心情/好感；
- 关注期 → `focus_sessions` 硬逻辑。

> 原则：**协议保留，行为规则删掉**。
> 跟「数据怎么交给系统」有关的（MEMO/THINK/MOOD/CALL/sticker/NapCat）不能删；
> 跟「怎么说话/什么时候接」有关的，交给硬逻辑 + 心情 + pipeline。
