# 24 小时收发件人标签审核（2026-11-27）

用户要求：「打印下 24 小时标签情况，审核是否有误导她理解的标签或者人称。」

## 0. 取样口径

- 源：`data/llm_trace/2026-11-26.jsonl` + `2026-11-27.jsonl`，只取 `key` 以 `group_` 开头的请求；
- 从**实际进 prompt 的 user 消息**里抽 `→ 收件人` 行，时间窗 26h，去重后 **2151 行**，
  取最后 500 行做逐行审；
- 三个渲染口都覆盖到了：
  - 主上下文/分段：`[n] #mid 名字(qq) → 收件人: 内容`（`group_scene.history_lines`）
  - 判读上下文：`1. ⭐名字(qq) → 收件人: 内容`（同一函数，前面加序号）
  - 群聊现场：`名字 → 收件人：内容`（`group_scene` 卡片，全角冒号）

## 1. 统计

| 项 | 数 |
|---|---|
| 解析成功的标签行 | 475 / 500（25 行是块标题/续行，不含 `→`） |
| `→ 大家` | 402（85%） |
| `→ 你`（⭐） | 73（15%） |
| `→ 大概某人`（低置信兜底） | 0 |
| `→ 某人?`（不确定） | 0 |
| `→ 具体某人`（硬逻辑/审核确定） | 0（都收敛成「大家/你」） |
| `〔已回〕` | 今天全量 trace 里出现 **278 次**（该标记工作正常，样本里恰好没抽到） |

## 2. 发现的问题

### 2.1 【真 bug，已修】@ 别人被记成「→ 你」

证据（2 例 / 475 行）：

```
萌萌香被迫单推人 → 你：@冬眠耗子不起床(767566774)
沐兮不是小龙娘   → 你：还有亲自己唉 @下个路口见⁧⁧喵⁧⁧(2402941099)〔引用 大肥鱼 12:42 的消息…〕
```

两例的正文都 @ 了**别人**，却被标成对她说。

**根因**（`plugins/chat/__init__.py` 记消息处）：

```python
if event.is_tome():                      # ← NapCat 上这个信号不可靠
    _atq = [_me] + [q for q in _atq if q != _me]
```

`event.is_tome()` 在 NapCat 上不只「@ 她」为真：**引用她也为真**，实测「@ 别人」也出现过 True。
旧写法只要 `is_tome` 就把她自己插到 @ 名单最前 → 收件人变成「你」，真正的 @ 对象丢了。

**修法**：@ 名单里真有她才排第一；@ 的是别人就保留别人；一个 @ 都没有（纯引用/适配器兜底）才补她自己。

### 2.2 【已修】昵称里混零宽字符 → 人称容易串

- 475 行里 **80 行（17%）** 的发言者名字含不可见字符（U+2067 / U+2069 / U+115F 等）：
  `下个路口见⁧⁧喵⁧⁧`、`下个纪元见ᅠ⁧~喵⁧`、`屑萌新⁧喵⁧`、`柳如烟⁧我喜欢你⁧`。
- 影响：① 名字看起来一样、实际不同；② 模型复述/区分人时容易串；③ 同名不同号（见 2.3）更难分辨。
- 修法：新增 `group_scene.clean_name()`，在**入库时**（`observe`）和**渲染时**（`history_lines` / 现场卡片）
  都清掉零宽/格式字符，正常中文与 emoji 不动。

### 2.3 【未改，记录】同一个 QQ 有多个昵称

抽样里 18 个 QQ 出现过 ≥2 个昵称，最典型：

| QQ | 昵称 |
|---|---|
| 100000003 | 阿明 / 优妮 |
| 100000009 | 下个纪元见ᅠ⁧~喵⁧ / （多个带零宽变体） |
| 2402941099 | 下个路口见⁧⁧喵⁧⁧ / （多个变体） |
| 100000006 | ヽ(｀д´)ノ / ヽ(｀д´)ノ / … |

- 风险：她可能把同一个人当成两个人（好感/称呼会分叉）。
- 现状：`profiles.call_of(qq)` 已有「我对他的称呼」覆盖机制，但**没在这里统一使用**；
  改法（未做，属于产品决定）：渲染时统一用 `profiles.call_of(qq) or 昵称`。
- 0.5 修：零宽字符清掉后，「下个纪元见~喵」的多个变体已经会收敛成同一个显示名。

### 2.4 【设计内，不改】纯命令词被标「→ 你」

`今日运势`、`档案卡片`、`查看档案`、`绘图` 等 12 条被标成 `→ 你`。
这是对的：这些命令确实由她执行。只是它们混在「聊天」里，
若模型把它当闲聊复述，会出现「好呀我这就给你看运势」这种废话。
现状可接受；真要更干净，应该在 prompt 里单列「命令 = 她要执行的动作，不要复述」。

### 2.5 【合理】「→ 你」里 67% 没有 @/引用

73 条 `→ 你` 里只有 24 条正文带 `@她` 或「引用她」，其余 49 条是**正文点名/玩梗**：

```
ヽ(｀д´)ノ → 你：饿，我要吃鱼，吃你个魔鱼
ヽ(｀д´)ノ → 你：鱼你不是自己有吗？
格林 → 你：我要亲你一口，可以吗〔引用 大肥鱼 11:14 的消息…〕
```

这一批是在玩「吃鱼」的梗，确实在跟她说话，属**软信号命中**，不是误标。
唯一要留意的是「杂鱼」这种群内互骂梗也可能被算进来 —— 观察即可，先不改。

## 3. 人称约定是否一致

- `你` 在标签里**始终指她自己**（她自己的话也渲染成 `你 → 大家`）；
- `segments.py` 的规矩写的是「带 ⭐ / 「→ 你」的才是说给你的；「→ 某人 / → 大家」是别人之间的对话」；
- `mood_judge` 的 prompt 写的是「格式：`谁 → 收件人：内容`。**`→ 你` 才是对她说的话**」；
- 两处口径一致，无冲突。

## 4. 结论

| 问题 | 严重度 | 处置 |
|---|---|---|
| @ 别人被记成「→ 你」 | 高（会让她以为整段都在跟她说） | ✅ 已修（2026-11-27） |
| 昵称零宽字符 | 中（人称串、同名难分辨） | ✅ 已修（入库+渲染双清） |
| 同一 QQ 多昵称 | 中 | ⏸ 记录，待定（建议统一走 `profiles.call_of`） |
| 纯命令词标「→ 你」 | 低 | ⏸ 设计内 |
| 「→ 你」无 @ 的软命中 | 低 | ⏸ 观察 |
