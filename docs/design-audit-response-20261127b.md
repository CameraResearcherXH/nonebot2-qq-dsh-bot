## 二、部分真（说对了现象，结论过强）

### 5. 「卡尔曼沦为残差却保留整套 P/Q/R/K」——复杂度真，但「凭什么留着」有答案

`P` **不是装饰**：它决定 `K = P/(P+R)`，而 `K` 是**残差项权重**：

- 同一话题连续判读 → `P` 每窗衰减 → `K` 变小 → **同样的话影响递减（脱敏）**；
- 静默 / 每 20 窗 → `P` 回补 → 下一句重新「有分量」；
- `|impact|≥2` → `P` 再补一点（`MOOD_P_EVENT_BOOST`，只补不降）。

删掉 `K` 之后：连发十句和只说一句效果一样，`dv` 变成固定值 —— **好感的「尾部突变（一见钟情/心碎，`|dv|≥0.30`）」通道也会消失**。
所以「过度设计」这个评价**部分成立**（复杂度确实高、cadence 那层可以砍），但「整台状态机是摆设」不成立。
已把这段写进 §3.1 表下面（2026-11-27 补）。

### 6. 「情绪是自指环、正反馈风险被吞下」——文档确实没讨论，但「能自激荡」有条件

- 环是真的：她写 THINK → 判读 THINK → 改 v → 状态卡写「你心情差/语气冷」→ 更容易写冷的 THINK；
- 但限速件不少：半衰期 30min/2h/6h、`P` 衰减（脱敏）、`relevance<0.25` 不推好感/记忆、锚点每窗回拉、`MOOD_HARD_CAP`；
- **文档确实只讨论了「防回声」（ADR-029/042），没把「正反馈失控」当风险写**。

处置：§8.1「已知债」里正式登记这条，写明「靠参数被动限速，没有主动刹车；要治就加『连续 N 窗同向 → 强制回中』」。

### 8. 「预算名存实亡，退化成观测」——措辞残留真，结论过强

- §3.3 **261-268 行**早就写了「2200 只约束动态块」「不要当总闸」——审计没读到这段，或者被 320 行的旧措辞带偏了；
- 「默认 `CTX_ENFORCE=0`」是 **tuning 默认**，**线上 `.env` 是 1**（会裁块级）——拿默认值推线上不准确；
- 但「整份 prompt 没有硬上限」是对的（`CTX_SOFT_CAP=2700` 只告警）。

处置：320 行措辞已改；§8.1 把 enforcement 边界写清楚（真正会裁的只有动态块池 + 块级裁剪）。

## 三、理解问题（代码里有，但默认不跑）

### 9. 「只有一条更新链路」vs 五六条写入口

| 函数 | 实际状态 |
|---|---|
| `set_value_from_judge` / `apply_delta` | 同一函数里的两条分支，由 `MOOD_UPDATE=v2|delta` 切换（**delta 是回滚档**） |
| `bump_by_emotion` | `MOOD_FROM_JUDGE=true`（默认）时**只写 label、不动数值**（`mood.py:1570` 直接 return 当前 v） |
| `judge_message_mood` | 返回值只在 `MOOD_FROM_JUDGE=false`（回滚）时才用（`chat:5529`） |

**默认配置下数值链路确实只有一条**（THINK → impact → `set_value_from_judge`）。
「文档说只有一条、代码里还有 5 个函数」是把「存在的函数」当成「在跑的链路」。
不过「没写清有回滚分支」这点可以改进，已在 §8.1 登记。

处置：§8.1 登记为「已知债」，写明「不上线就删公式和参数，只留 v1」——但删不删是产品决定。
