# 检索与档案审计：记忆 / 图书馆 / 人 / 好感·心情 / 档案

日期：2026-11-25 20:35｜起因：档案和记忆重复率高；档案不该什么都写

---

## 1. 五个块现在各管什么

| 块 | 数据源 | 触发 | 内容 |
|---|---|---|---|
| **记忆** | `memory_v2.recall(query, speaker_qq, gid)`（角色脑 sqlite） | 每轮 | 这个人相关的 4 条事件（时间 + 一句摘要） |
| **图书馆** | `agent_client.recall`（RAG v3） | 只在「像在问事/提旧事」且 `power_on("library")` | 语料库 3 条事实，带「不是你我现在的事」警告 |
| **人** | `profiles` + `bond_notes` + `white_moon` | 每轮（有收件人） | 称呼 / 身份 / 性格 / 好感词 / 印象最深 1 条 / 白月光 1 行 |
| **好感·心情** | `mood.status_block` | 每轮 | 心情水平 v、a/d、她自己写的感觉、刚才那下（Δ 描述）、她的 THINK、好感数值+趋势 |
| **档案事情** | `bond.notes` | 判读后 | 只收 `|Δ| ≥ 0.15` 的大波动事件 |

## 2. 发现的重复（已修）

### 2.1 档案块的「印象最深」是再查一遍记忆

`services/reply_pipeline.py` ③ 原来：

```python
_hits = memory_v2.recall(_nm, limit=3, speaker_qq=..., gid=...)
_best = max(_hits, key=lambda h: h["salience"])
lines.append(f"· 你俩印象最深的一件事：{_best['summary']}")
```

下面的「记忆」块又查一次同一个库 → 同一件事在 prompt 里出现两遍。

**改法**：档案块改读 `profiles.get_bond(qq)["notes"]`，取 `|delta|` 最大的一条。
档案和记忆从此不再查同一个东西。

### 2.2 档案收得太杂

| 入口 | 以前 | 现在 |
|---|---|---|
| MEMO 判读回流 | `|Δ| ≥ 0.10`（任何情绪） | **`|Δ| ≥ 0.15`**（只有 impact±2 的大事） |
| `/记住 <事实>` | 同时写记忆 + 档案 | **只写记忆**（事实不是印象） |
| 看 B 站视频 | 同时写记忆 + 档案 | **只写记忆** |
| `profile_miner` 挖「事情」 | 中性事件也写 | **只写带明确情绪的**，`neutral` 跳过 |

新门槛在 `core/tuning.py`：`PROFILE_NOTE_MIN_DELTA=0.15`，
`profiles.add_bond_note` 里统一拦截（带 Δ 的调用一律先过门槛）。

## 3. 好感 / 心情块：Δ 与 v 的分工

| 展示 | 用的是什么 | 说明 |
|---|---|---|
| `· 心情：平平的（+0.12）` | **v（水平）** | 当前心情 |
| `· 你现在的状态：…` | a / d | 唤醒、掌控（只记录） |
| `· 你自己写的感觉：…` | 她的 MEMO | 她自报 |
| `· 刚才那下：被夸得有点飘` | **Δ 的语义描述** | 不是水平 |
| `· 你心里那句话：…` | 她真实的 THINK | 不再用 judge.mind |
| `· 你对 XX 的好感：+0.62（回暖）` | affinity + 趋势 | 数值 |
| 档案 `· 你对他的好感：很亲近` | **好感词** | 语义描述 |

设计上「数值在状态卡、词在档案」，**不是重复**；但如果以后觉得啰嗦，可以只留一边。

---

## 4. 仍然存在的边界

1. **记忆和图书馆可能命中同一件事**：来源不同（角色脑 vs RAG 语料库），
   图书馆块已经带「不是你我现在的事」警告；暂不合并。
2. **人检索**（`recall` 带 `speaker_qq`）依赖 P4 的结构化过滤；BM25 没命中时走
   `recent_about` 兜底，prompt 里会标「关键词没命中，按时间给的」。
3. 档案变稀疏后，「印象最深」可能长期为空——这是预期的：没有大波动就不编。
