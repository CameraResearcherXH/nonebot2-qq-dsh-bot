# 完整 Pipeline：一个不断累加的自我

> 这份文档回答一个问题：**她凭什么这样回话？**
>
> 不是"人格卡 + 几句上下文"，而是五层数据互相喂养：
> 记忆决定她记得什么 → 档案决定她对谁什么态度 → 心情决定她今天想不想说 →
> 场景决定她此刻在跟谁说话 → 表达决定她用哪种口气。
> 每一次互动都会写回这五层，下一轮再读出来 —— 所以是**累加**，不是无状态问答。

---

## 一、五层数据：谁写、谁读、存在哪

| 层 | 模块 | 写（谁更新） | 读（进 prompt 的哪块） | 存储 |
|---|---|---|---|---|
| **事实层**<br>发生过什么 | `memory_v2` | 她自己的 `[[MEMO]]`；图片识别；称谓变化 | `memory_prompt()` → 「你长期记住的事」 | `data/memory/`（index + 每条一个 json） |
| **关系层**<br>我跟他是什么关系 | `profiles` | 每条消息自动 upsert；`profile_update` 工具；相处印象 `add_bond_note` | `render_card(brief/full)` → 「这一条在跟你说话的人」 | `data/profiles/<qq>_profile.json` / `_bond.json` |
| **自我层**<br>我在他面前是什么样 | `profiles.stance` + `expression` | `profile_update(stance=…)`；`expression.mine()` 每 40 条挖一次语气 | `render_card` 的「你在他面前」；`expression.render()` → 「说话风格参考」 | 同上 / `data/expression/` |
| **状态层**<br>聊到哪了 / 我什么心情 | `conv_state` + `mood` | 每 6 条压一次滚动状态；情绪事件改心情 | `conv_state.render()` → 「这段对话之前的状态」；`mood_prompt()` → 「心情」 | `data/state/` / `data/mood.json` |
| **场景层**<br>此刻谁在跟谁说话 | `group_scene` + `chat` 上下文队列 | `observe()` 每条群消息；审核 LLM 纠错 | `format_block()` → 「群聊现场」；`recent_group_msgs` → 「历史对话」 | 内存（重启由 `dialogue_log` 补） |

辅助但关键的两条：

- `dialogue_log`：**所有对话原文**（群 + 私聊），是"翻聊天记录"和主动私聊找素材的来源。
- `chat_switch`：她对某个群/某个人「安静」的状态（含原因和起因人）。

## 二、一次回复的完整数据流

```
群里有人说话
  │
  ├─ chat._need_reply
  │    ├─ 破冰检查：chat_switch.maybe_thaw（他道歉了？→ 解除安静）
  │    ├─ 记群上下文 recent_group_msgs（时间 + 人 + #消息号 + ⭐在叫她）
  │    ├─ group_scene.observe（谁→谁、线程、收件人）
  │    ├─ dialogue_log.log_msg（落盘原文）
  │    └─ expression 计数（每 40 条后台挖一次语气）
  │
  ├─ chat._session_worker（队列 → 防抖 → 合并连发）
  │    ├─ profiles.upsert / touch（档案）
  │    ├─ mood.judge_message_mood（关键词兜底）
  │    ├─ scene_auditor.audit_recent（审核 LLM 纠正"谁对谁说"）
  │    ├─ group_scene.snapshot + addressee_line（现场 + 收件人）
  │    ├─ build_prompt（时间/人称/记忆/心情/当前消息）
  │    └─ call_llm
  │         ├─ 人格（services/Personality）
  │         ├─ ▍00 菜单 / 01 长度 / 02 该不该接 / 02b 语气 / 02c 接不上 / 02d 注意力
  │         ├─ ▍00b 你在哪（群号/消息号，工具参数直接用）
  │         ├─ ▍00c 你的地盘（ALLOWED_GROUPS / ALLOWED_PRIVATE / 主人）
  │         ├─ ▍00d/00e 安静状态（强制 stay_silent 时锁 tool_choice）
  │         ├─ 【群聊现场】【历史对话】【滚动状态】【人物卡】【表达学习】
  │         └─ 工具：stay_silent / chat_switch / sticker_save / vision_source / napcat…
  │
  ├─ parse_reply
  │    ├─ items（text / sticker / voice / at / reply）
  │    ├─ memos  → memory_v2 + bond + mood（**带「群号:」前缀**）
  │    ├─ calls  → profiles 称谓 + stance
  │    ├─ focus  → 她在回哪一条
  │    └─ silent → 不说话（但记忆照写）
  │
  └─ 发送（分条 / 引用 / @ / 合并转发 / 表情）
```

图片走同一条后半段，只是前半段换成：
`vision_agent.process_image → 取图 → qwen/GLM 识图 → trace.moe → 多源 report → 入队 → call_llm（媒体分支）`。
媒体分支也会注入「人物卡 + 表达学习 + 滚动状态」，所以**看图说话和打字说话是同一套语气**。

## 三、翻页与自省：别让她以为"只有这几条"

这是最容易被她误解的地方 —— 只给 4 条记忆，她就真的以为"我只记得 4 件事"。

| 她想要 | 怎么做 | 返回里会看到 |
|---|---|---|
| 翻更多记忆 | `[[MEMORY|关键词]]` → `[[MEMORY|关键词|翻页2]]` | 「相关记忆一共 N 条，这里只放最强的 4 条…」 |
| 看某条全文 | `[[MEMORY|展开|编号]]` | 该条完整内容 |
| 按时间翻 | `[[MEMORY|前天上午]]` / `[[MEMORY|3天前]]` | 那段时间的目录 |
| 翻档案 | `[[PROFILE|名字]]` → `[[PROFILE|名字|翻页2]]` | 相处印象一页 6 条 + 总数 + 下一页提示 |
| 翻聊天记录 | `[[HISTORY|20]]` / `[[HISTORY|50]]` | 更早的原始对话（不压缩） |
| 看我在各处什么样 | `/表现`（她自己看）/ 自动注入「说话风格参考」 | 群 / 人两种作用域的语气 |

> 原则：**每一块只要还有更多，就必须在结尾写清"一共 N 条、怎么看剩下的"**。
> 否则她的判断会建立在"信息已经完整"的错觉上。

## 四、主动接话：不是固定句子，是先翻完再开口

`services/proactive.py` 的 `pick()` 先算"要不要找"：

```
分数 = 心情(chatty) × (0.5 + 1.2×亲密度) × 注意力漂移档位
闸门：静音中 / 当天次数 / 冷却 / 刚聊完(<2h) / 太久没聊(>72h) / 最后一句是她说的 / 不够熟(<0.45)
```

决定找了以后，`prompt_block()` 把**判断依据**一起给她（这才是"不是固定语句"）：

1. 你俩的关系（`render_card full`：人 / 事情 / 关系 / 你在他面前 / 注意）
2. 跟他有关的记忆（`memory_v2.recall`，用最近一句真人消息当 query）
3. 上次聊到哪了（`conv_state.render`）
4. 我现在的心情（`mood_prompt`）—— 心情不好可以找他倾诉，这本身就是正当理由
5. 最近的对话原文（`dialogue_log`）

所以同一个"主动找人"，对不同的人会是完全不同的内容：对 A 撒娇、对 B 正经、对 C 吐槽 —— 因为关系、相处印象、她在对方面前的样子都不一样。

> 群里不做这件事（群里已有 `_random_chat_loop`：看当下对话插一句）。
> 私聊是"看关系和时间"，两者判据不同，混在一起必然互相干扰。

## 五、安静与破冰：她不会无缘无故不说话

- `chat_switch` 支持 **群 / 人** 两种粒度 + 限时（`until`）。
- 安静时**照常读**：上下文、现场、记忆、心情都更新 —— 只是不回。
- 「真不回」落在 API 层：`tool_choice={"type":"function","function":{"name":"stay_silent"}}`。
- 状态里存 `reason`（为什么）和 `by_qq`（谁惹的），会写进 system：
  「群 100000017：被他那句烦到了（起因：阿明），到 11-19 18:00 自动恢复」。
- **破冰**：`maybe_thaw()` 检测道歉/哄人关键词（对不起 / 抱歉 / 我错了 / 别生气 / 原谅 / 和好…），
  满足条件自动解除，并在 prompt 里给她台阶：「他刚在哄你/道歉了…想原谅就正常说话；还不想理就 stay_silent」。
  只解除"因这个人而起"的安静；主人道歉一律给台阶。

## 六、群聊标签（发件人 / 收件人）怎么用

`group_scene.observe` 记的是 `qq → to_qq / to_reason(at|reply)`。这些标签有三个用途：

1. **现场渲染**：「线程1｜3分钟前｜阿明、小柚子」+「@小柚子 你买了？」→ 她知道这句是问谁的。
2. **审核 LLM**：修正 `to_reason=大家/不确定` 的模糊情况（`scene_auditor.apply_audit`）。
3. **记忆归属**：写 MEMO 时带 `（群号:XXX）` 前缀 → `memory_v2.group_ok()` 才能实现
   「这个群的事只在群里用」。以前过滤逻辑存在但**没人写前缀**，等于没隔离；现在补上了。

## 六·补、重启不失忆：现场从对话日志补回

现场（线程 / 谁→谁）只在内存里，**一重启就空**。以前重启后 `/测函数 现场`
只剩「窗口 1 条」，审核也只能看到最后一句 —— 用户 2026-11-19：
「打印还是打不到那条，明明 10 条间隔」。

现在 `group_scene` 发现某个群的现场是空的，就按**条数**（不是按天）从
`data/dialogue/*.jsonl` 读回最近 `SCENE_SEED_LIMIT`（默认 24）条：

- 时间戳保留原值 → 卡片上的「5 分钟前」是真的，审核里的「距上一句 X 分钟」也对；
- 名字去掉日志里的 `阿明(1001)` QQ 尾巴，审核才能按名字映射回 QQ；
- 同一个 `mid` 只进现场一次（NapCat 回显 / 识图+chat 各记一遍 / 补现场撞活消息都会去重）；
- 补过就 `seeded` 计数，卡片标题显示「· 日志补 N 条」，不用再猜为什么只有一条；
- `[图片]/[视频]` 也留一条占位（`no_audit=True`）：图不进现场，
  下一句「这猫躺得比我还会摆烂」在审核眼里就是凭空冒出来的。

---

## 六·补2、看 20 条再判断（不是五六条）

用户 2026-11-19：「线程1 和我们的硬逻辑应该同时看 20 条来判断，而不是现在的五六条。」

- `SCENE_WINDOW_MSGS=20`：**线程视图**（卡片 / prompt 的「线程1」那几行）、
  **硬逻辑**（话题重合、谁在接谁）都按最近 20 条算，和 `SCENE_AUDIT_MAX_MSGS` 对齐。
  最新那条线程给足 20 句，其它线程 4 句（别被老线程撑爆）。
- 冲人短句（≤12 字，如「找打了」「欠揍」「你完了」）不再只认「上一句是谁说的」：
  先看**最近 20 条里被正文点到名字的那个人**，判给他（`to_reason=recent_mention`，
  置信度 0.55，仍会进审核）。真机例子：老王「找打了」其实是对「肥鱼」说的。
- 审核 prompt 里也加了同一条规则（双保险）。

## 七、白名单 ≠ 只有他们有档案

- `ALLOWED_GROUPS / ALLOWED_PRIVATE`：**她在哪些地方出现**（默认 prompt 的表现范围）。
- `profiles`：群里**每个人**每条消息都会 `upsert_profile` + 相处印象；
  `render_card` 按"当前说话人"注入，不依赖白名单。
- 所以：白名单决定"她在哪儿说话"，档案决定"她怎么对待眼前这个人"。

## 八、开关总表

| 开关 | 作用 |
|---|---|
| `VISION_REPLY_MODE=llm` | 识图只负责"看见"，回不回由她定 |
| `STICKER_DECIDE=llm` | 表情包收不收由她定（`sticker_save`） |
| `CHAT_OFF_*` | 安静开关 / 强制 stay_silent / 被叫到时给选择权 |
| `PROACTIVE_*` | 主动私聊（默认 `DRY_RUN=true` 先演练） |
| `CONV_STATE_*` / `EXPRESSION_*` | 滚动状态 / 表达学习 |
| `ATTENTION_*` | 注意力漂移档位（也影响主动接话的分数） |
| `TRACE_*` | 以图搜番的采信阈值 |
| `SCENE_SEED_*` | 重启后按条数从对话日志补回现场（默认开，24 条） |
| `SCENE_WINDOW_MSGS` | 线程视图 + 硬逻辑看最近多少条（默认 20，和审核对齐） |
| `API_USAGE_*` | 余额/用量工具：记账文件、保留天数、超时 |

## 十、已知缺口（下一步）

1. **记忆没有结构化字段**（只有 `about_qq` + 文本前缀）。想做"按人 / 按群 / 按时间 / 按情绪"
   四维检索，需要给 index 加 `gid` / `to_qq` 字段（现在靠文本前缀，够用但脆）。
2. **stance 需要她自己写**（`profile_update(stance=…)`）。可以在 `[[CALL]]` 里顺带更新，
   或在表达学习里自动归纳"她对这个人的语气"。
3. **主动私聊的"倾诉"内容**还没有专门的事件源（心情为什么差）。
   `mood.recent_shifts()` 有原始记录，可以接进 `prompt_block`。
4. `conv_state` 只压"对话"，不压"关系变化"。关系变化目前靠 `bond` 时间线。

## 十一、余额 / 用量（`api_usage` 工具）

主人私聊问「还有多少钱」「今天用了多少 token」→ 她调 `api_usage(days=1)`。

- **余额**：`GET {XAI_BASE_URL 去掉 /v1}/user/balance`（DeepSeek 官方）。
  `XAI_BASE_URL` 指向 `api.x.ai` 时官方**没有**余额接口，只回 key 信息 ——
  这时照实说「查不到，去 console 看」，绝不编数字。
- **用量**：供应商都没有公开的用量接口，所以 `llm.call_llm` 每次拿到 `usage`
  就 `api_usage.note_usage()` 记到 `data/api_usage.json`（按天 / 按模型 / 缓存命中）。
  只记**聊天主链路**，审核、状态压缩那些旁路没记（已知）。
- 工具 `scope=("private",)` + 只认主人：群里谁问余额都不答。

审核 prompt 里她自己说的话现在会标成 `你（机器人自己）`（以前是裸的 `你:`，
模型会当成某个叫「你」的群友，或者以为她没说话）；状态行也会写
「窗口 20 条（你自己 3 句，也一起给审核看）」，卡片上「审:某人」改成
「审:某人→老王」，判给谁一眼能看出来。

另外这一版修了一个「突然冒出来一句话」的源头：`sticker_admin` 的自然语言
「收表情」判定原来只要同时出现「收/存/收藏」+「标签/标记…」就算指令
（`block=True`），群里一句「收到，我标记一下」就会让她回
「好呀，把表情发过来吧」。现在要求 ① 有「表情/图」这个对象，或
② 动词在句首 + 标签词，且群里必须 @ 她。

## 十二、引用回复（评论某句 / 某图时）

协议：模型在回复开头写 `<reply:消息号>`，`parse_reply` 塞进 `item["replyTo"]`，
发送层换成 NapCat 的 reply 段（QQ 里那个灰引用框）。群聊上下文每行末尾带 `#消息号`。

什么时候引：

| 情况 | 做法 |
|---|---|
| 回**当前**这条 | 不用引（绝大多数） |
| 回**前面某条**（被刷上去了） | **必须**引（`newer_count > 0` 时由 `_reply_protocol` 强制） |
| **评价/吐槽某句/某图**（「这图笑死」「你这话说的」） | 引那一条，否则别人不知道在说哪句 |
| 当前这条是**图片/视频** | 发送层兜底引用（`chat._auto_rid`，和「被 @ 自动引用」同一套） |

`_auto_rid` 现在除了 `ev.is_tome()`，**图片/视频**也会自动挂引用 ——
「这猫躺得比我还会摆烂」不引那张图，群友根本不知道在说哪张。

## 十二·补、识图：角色名不确定就不说

用户 2026-11-19：「她觉得 trace.moe 给的角色名不太确定，可以不回复角色名相关信息，正常回复。」

- trace.moe 只是「疑似命中」（`confidence != high`）→ 多源报告里明说
  **「角色名不确定：完全可以不提名字，直接聊画面/吐槽/接梗」**；候选角色 >2 个也说一句。
- 这种情况 **角色名不写进 `desc`**（desc 会进群聊上下文和长期记忆，写错要污染很久），
  `desc` 标「（《作品》，仅猜测）」。
- 高置信（相似度 ≥0.90 且多帧一致）照常写角色名。

## 十三、`/上传文件`（QQ 文件 → data/，仅主人）

```
/上传文件            → 挂 3 分钟等待（UPLOAD_WAIT_SEC）
（3 分钟内发一个 QQ「文件」）→ 落到 data/uploads/YYYYMMDD/<文件名>
/上传文件 + 同一条带文件 → 直接存
```

- 只认主人（`is_owner`），别人发的文件一律不接（群里谁都能发文件 = 公共投毒口）。
- 文件名消毒：`Path(name).name` + 去掉 `\ / : * ? " < > |`，写不出 data/ 之外。
- 重名不覆盖（追加时间戳）；超过 `UPLOAD_MAX_MB`（默认 200MB）拒收。
- 下载地址：file 段自带 `url` 就用；没有就 `get_group_file_url` / `get_private_file_url`。

## 十四、导入成套表情（按标签分文件夹）

用户 2026-11-19：`/上传文件` 传上来一套 AI 表情（`data/uploads/20261119/jing_output_img/`
下面 `开心/ 生气/ 疑惑/ 问候/ 难过/`，每个里面 `1.png…18.png`），要能变成她真的能发的表情。

```
/导入表情 data/uploads/20261119/jing_output_img
```

- **标签取文件夹名**（`FOLDER_MAP`）：疑惑→思考、问候→打招呼、开心/生气/难过原样；
  认不出文件夹才退化成「文件名关键词 → 兜底搞怪」。
- 从 `data/uploads` 导入会**自动用复制模式**（uploads 是 `/上传文件` 的暂存区，会被清）：
  文件复制进 `data/stickers/<标签>/<md5>.<ext>`，index 指向新路径，原文件删了也不影响。
  其它目录（`data/memes`）仍是原地索引，省磁盘。
- 复制时把长边 > `STICKER_MAX_SIDE`（默认 512）的**静态图**缩小（AI 图常 1024²/1MB+，
  QQ 反正会压小，传得还慢）；**GIF 不动**（压了就没动画）。
- 按内容 md5 去重：同一张图在多个标签文件夹里只收一次，重复导入全是 `dup`。

## 十五、心情是她自己写的一句话（不是固定枚举）

用户 2026-11-19：「心情不能是我们指定的几种，不能在我们限制的几种心情范围内。她要自己有写心情的权利。」

以前：`[[MEMO|emotion:...]]` 只认 9 个词（happy/sad/…），心情是 `value` 数值 +
`mood_prompt()` 里写死的四档文案（「你现在心情特别好」「有点低落」）。

现在：

- **`[[MOOD|被夸得有点飘，但还装作没事]]`**：新协议，回复末尾另起一行写，
  用户看不到。存的是**自由文本**（≤`MOOD_LABEL_MAX`，默认 60 字）。
- `[[MEMO|emotion:自由描述|text:…]]` 里的 emotion **也可以写自己的话**
  （「烦，但还得装没事」），不再强制从 9 个词里挑 —— 固定词只用来估数值方向。
- `mood_prompt()` 优先用**她的原话**：「（你现在的心情：被夸得有点飘… 按这个感觉说话）」；
  没有原话才退回按数值的粗略描述。
- `/心情` 显示原话；数值单独标成「语气值（只影响活泼/冷淡，不是心情本身）」。
- 原话按 `MOOD_LABEL_TTL_HOURS`（默认 12h）过期，别让三天前的心情一直挂着；
  `_decay()` 以前只回 `value/updated_at`，会把 label 一起丢掉 —— 已修。
- 自由描述也会按字面给数值一个小推力（`_delta_from_text`，±12 封顶），
  免得「烦死了」和「好开心」对数值完全一样。

## 十六、心情判读（第三方 LLM，影子运行）

用户 2026-11-19：「ai 自己写心情值会崩，它会乱写。不如让她写自己是什么感觉、什么事的心里话，
然后放一个新对话模型根据她的心里话判断心情名词和阈值 1.0 / 0 / -1.0，两位小数。
先把这套搞定，准了再接进心情系统。」

分工：

| 谁 | 干什么 |
|---|---|
| 她 | 只写**感觉 + 心里话**：`[[MOOD|…]]`，或 `[[MEMO|emotion:…|think:心理活动|text:…]]` |
| `services/mood_judge.py` | 第三方模型判：`word`（具体名词，4~10 字）+ `value`（-1.00~1.00，两位小数） |
| 判读输入 | 她的原话 + `think` + **最近 20 条群聊**（和审核窗口同口径）+ 上一轮判读 |
| 现状 | **影子运行**：只写进 `mood.json` 的 `judge` 字段，不改变行为 |

- **她没写也能判**（用户 2026-11-19：「是要根据聊天看最新吗，还是说没有按消息条数拉。
  我建议拉 20 条来看」）：`mood_judge.scene_lines()` 按**条数**拉最近 20 条 ——
  群聊走 `group_scene.recent_messages`（带「谁说的」，还包含她自己那几句），
  私聊/现场空退回落盘日志 `dialogue_log.load_recent`。不是按时间切。
- 三道闸门：`MIN_INTERVAL`（同会话 20s 一次）→ 她没写时还要过 `REFRESH`
  （默认 300s 才用群聊重判一次）→ 窗口 `CTX`（20 条）。
- `/测函数 心情`：对照「她的原话 / 判读名词+阈值+依据 / 老语气值」，
  并显示「按条数拉了几条 + 最后 3 条原文」；`重判` 现在**她没写也能跑**（按群聊判）。
- 记忆的情绪刻痕：判读结果够新（`MOOD_JUDGE_FRESH_SEC`）就用 `|value|` 当 `emotion_weight`，
  否则退回 MEMO 自报的 emotion。
- 验证准了之后的切换点只有一处：`mood.mood_factors()` / `bump_*` 改成读 `judge.value × 100`。

## 十七、档案卡片（function calling + 头像 + 十件事）

- 工具 `profile_card(name=…)`（私聊 + 群）：`name` 留空 = 当前说话人（「我的档案」），
  填名字/QQ = 看别人的（「小明的档案」/ 他 @ 了某人）。返回文字 + 图片路径，
  想发就再调 `send(image=路径)`。
- 卡片左上角现在贴**真 QQ 头像**（`q1.qlogo.cn` → `q.qlogo.cn` 三个源轮着试，
  缓存 `data/avatars/<qq>.jpg`，`AVATAR_TTL_DAYS` 天更新）；取不到就退回「名字首字」圆，
  不会把整张卡搞挂。取头像要走网络，调用处统一 `asyncio.to_thread`，不卡事件循环。
  - ⚠️ 必须 `trust_env=False` + 自带 UA：容器里只要设了 `HTTP_PROXY/ALL_PROXY`，
    httpx 默认就走代理 → 连 qlogo 直接失败（项目里其它出网调用也是这么写的）。
    缓存文件坏了（0 字节/半截图）会删掉重下一次。
  - 拿不到会打一条 WARNING（每个 QQ 一次）；`/测函数 档案` 里有一行
    `头像：已缓存 5.9KB｜(140,140)｜3.2h 前` 或 `头像：下载失败：…`，不用猜。
- 「事情」从 4 条 → **最近 10 条**（`PROFILE_CARD_EVENTS`）；文字版 `full` 卡同步 10 条。
