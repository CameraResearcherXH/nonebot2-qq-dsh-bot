# MaiBot（麦麦）拆解：哪些值得抄、哪些不值得

> 分析对象：`~/hzy/MaiBot-main`（MaiBot v1.4.7 / WebUI v1.10.7，**GPL-3.0**）
> 分析日期：2026-11-19
>
> ⚠️ 许可证：MaiBot 是 GPL-3.0。**只借鉴设计思路，不要整段复制代码**——
> 一旦复制进本项目，整个项目都要按 GPL 开源。下面所有条目都是「思路 + 我们自己实现」。

---

## 一、它的分层（先看骨架）

```
消息层  chat/message_receive + chat/debounce（防抖合并）+ scenes/（群/私聊分流）
   ↓
决策层  maisaka/runtime + turn_trigger（查看频率/静默唤醒）+ planner（工具式：reply/wait）
   ↓
表达层  chat/replyer（生成）+ reply_supplement（@/图/表情的发送编排）+ expression（表达学习）
   ↓
记忆层  A_memorix（长期记忆）+ person_profile（画像）+ heuristic_injector（印象→召回）
   ↓
学习层  learners/（expression 表达风格、jargon 黑话）
   ↓
表情层  emoji_system（VLM 打标 + 语义向量匹配 + 冷却抽样）
```

关键设计取向：**「最像而不是好」**。所有机制都在回答一个问题——
「一个真人在这条消息上，会开口吗？会怎么开口？」而不是「怎么答得最全」。

## 二、P0：直接解决我们正在痛的问题

### 1. 查看频率（ViewFrequency）：把「回不回」做成有惯性的概率

`src/maisaka/turn_trigger/view_frequency.py`（70 行，很好抄）

- 外部频率 = 配置的基础概率；
- **激活**：任何一次真正开始思考，内部频率从外部值起步；
- **衰减**：每跑完一轮扣 `1/16`；内部频率 > 0 时，外部判定**必定放行**（所以她会「连着说几句」）；
- **耗尽 → 恢复期**：每次判定按当时内部频率抽签，再 `+1/16`，16 次恢复到外部值；
- 结果：外部 0.3 时，连说 5 轮后自然安静；外部 1.0 时能连说 16 轮。

**我们现状**：`_interject` 用固定 `cooldown + random() < prob`，没有「刚说过话就自动收敛」的惯性，
所以要么一直不说话，要么连着插三句。

**落地**：在 `plugins/chat` 加一个 30 行的 `ViewFrequency` 类（gid → 状态），
把插话概率改成 `vf.decide(external_prob)`；`session_last_reply` 时调 `vf.activate()`。

---

### 2. 静默唤醒：预测「下一条消息该到了」，没到就给她一次开口机会

`src/maisaka/scenes/group/scheduling.py` 的 `_arm_silence_check` / `_check_silence`

- 用上下文窗口里**真实消息到达间隔**算平均值（当前窗口 + 上一轮窗口取均值）；
- 距最后一条消息超过这个间隔 → 多给一次判定机会（仍过概率）；
- 同一段静默只判一次；新消息来了重新计时；
- 判完仍然静默 → 按同一间隔等下一个截止点。

**我们现状**：插话循环是固定 15 秒 tick，群里没人说话时它会一直空转，
真有人说话时又可能刚好错过。

**落地**：`_random_chat_loop` 里维护 `mean_interval`，空闲超过 `mean_interval * 1.5`
再走一次「要不要开口」判定。这比固定 tick 更像人：**话题刚停下来的那一刻**最容易有人补一句。

---

### 3. 防抖 profiles：不同情况等不同的时间（我们刚被这个坑过）

`src/chat/debounce/controller.py`

| 情况 | 等待 |
|---|---|
| 安静开批（上一条 > 30s） | 2.0s（natural） |
| 活跃开批（上一条 ≤ 30s） | 5.0s |
| 同一个人续发 | 2.0s |
| **换人** | 0.5s（别人说话了，赶紧看） |
| **裸图（只有图没有字）** | **至少 4.0s**（等图片下载完） |
| @ 她 / 提到她 | 上限 1.0s（急） |
| 整批上限 | 8.0s（别无限等） |
| 纯表情包 | 不延长等待 |

**我们现状**：`MERGE_WINDOW` 一个固定值；裸图没特殊处理 →
这正是「我白饭都吃完了，怎么图还没加载出来」的土壤（图还没下载完就开始生成回复）。

**落地**：`_session_worker` 里的 `asyncio.sleep(MERGE_WINDOW)` 换成
`_debounce_wait(event)`，至少把「裸图 4 秒」「@ 1 秒」「整批 8 秒」三条加上。

---

### 4. Planner 正文补动作：模型说了但没调工具 → 用小模型补一次

`src/maisaka/planner_action_judge.py`（142 行）

- 触发条件：Planner 返回了正文，但**没有工具调用**；
- 只把「最近 5 条真实聊天 + Planner 正文」给 `fast_model`；
- 只允许输出 `reply` 或 `wait` 两个工具调用之一，参数按工具 schema 校验；
- 超时/无效输出**直接报错**，不偷偷改成静默（这点很值得学：不兜底）。

**我们现状**：模型输出 `[[CALL]]` 标记，解析失败就当作纯文本回复；
插话里「模型写了正文但没走 send」也会变成一句空话。

**落地**：在 `llm.parse_reply` 后加一步——有正文、无任何标记、且本轮应该「发消息」时，
用便宜模型判一次 `reply / wait`（我们的 `reply` = 直接发这段正文）。

---

### 5. 上下文压缩：压成 5 类「可接续状态」，而不是截断

`src/maisaka/context/compaction.py` + `prompts/.../context_compaction.prompt`

五类固定字段，每条信息只放一处：

```
topics      当前话题（含指代关系）
background  关键背景（人物/关系/事件；区分事实、转述、猜测、玩笑）
progress    进展与结论（完成状态以实际结果为准）
pending     未完事项（未答问题、承诺，注明归属）
agreements  对话约定（谁提的、还对谁有效、过期就删）
```

**我们现状**：历史超长就截断，只加一句「更早的已被折叠」+ 每日总结。

**落地**：`services/llm.py` 的历史折叠处，改成「每 N 轮把更早的段落压成这 5 类」，
存进 `data/state/<gid>.json`，每轮注入。好处：跨天/跨重启也能接上「上次说到哪、答应了什么」。

## 三、P1：让「像人」这件事再上一层

### 6. 表达学习（Expression）：学群友的**语气**，不是知识

`src/learners/expression_learner.py` + `chat/replyer/maisaka_expression_selector.py`

- 从群聊里挖「**这种场合，他们会这么说**」，存 `(situation, style, count)`；
- 回复前按当前上下文做**语义检索 + 加权抽样**，取 1~5 条；
- 注入位置是回复模板最前面的 `{expression_habits_block}`，并明确「参考语气，不要照抄」。

**我们现状**：`lorebook` 存的是**事实/设定**（谁是谁、什么梗是什么意思），
没有「说话风格」这一层；人格卡是固定的，学不到本群的口癖。

**落地（轻量版）**：
- 每 50 条群消息跑一次小模型：「从这些消息里挑 1~2 句**很本群**的说法，
  标上适用场景（吐槽/安慰/敷衍/接梗）」→ 存 `data/expressions/<gid>.json`；
- 回复时按当前消息的关键词/场景匹配 1~2 条，注入到 `_post_rules` 之前：
  `【这个群的人会这么说（学语气，别照抄）】…`；
- 和 lorebook 的区别要在 prompt 里写清楚：**lorebook 是「知道什么」，expression 是「怎么说话」**。

---

### 7. 黑话学习（Jargon）：带证据推断新词，还能判断「是在用还是在讨论」

`src/learners/jargon_learner.py` + `src/maisaka/jargon_context_matcher.py`

- 攒够 10 条消息成批处理，用 LLM 推断新词含义，**要求给出证据消息**；
- `is_jargon_reference_text()` 判断「这句话是在**用**这个词，还是在**讨论**这个词」——
  避免把「你说的『绝绝子』是什么意思」当成在用梗；
- 有并发闸门（同群互斥 + 全局上限），失败可重试但不会重复扣额度。

**我们现状**：`lorebook` 可以手写/让 LLM 写词条，但没有「从聊天里自动发现新词」的入口。

**落地**：给 lorebook 加一个 `auto_mine` 任务：每 N 条消息找「出现 ≥3 次、且不在词条里、
且不是常见词」的候选，让 LLM 结合上下文猜含义 + 证据，写进 `data/lore/<gid>.json`
并标 `source=auto`、`confidence`，低置信度不注入。

---

### 8. 注意力漂移档位（Attention Drift）：把「走神」做成可调风格

`src/maisaka/attention_drift.py`（124 行，纯文案表）

四个档位 `subtle / active / scattered / wild` × 三种回钩策略 `strict / balanced / loose`
× 三种短反应风格 `reserved / natural / lively`，组合成一段提示词。

关键约束（写得很到位）：
- 每次漂移**必须能从最近消息里找到触发点**；
- 漂移 ≠ 换话题：先抓一个突出的点，再拐回来；
- 每轮最多一次明显跳跃，**不能无视明确提问**；
- 不要自称 ADHD / 不要声明自己分心。

**我们现状**：`_post_rules` 里只有「只接一个线程」「别总结」这类硬约束，没有「允许她跑偏一点」的正向引导。
结果就是：要么老实回答，要么完全不接。

**落地**：在人格卡第十四节加一个「注意力档位」配置（默认 `active` + `balanced`），
按群覆盖（测试群可以调 `wild` 看效果）。这是**纯 prompt 改动，零风险**。

---

### 9. 引用概率公式：引用不是「被 @ 就引用」，而是按情境算

`src/maisaka/scenes/group/quoting.py`

八类基础概率 × 频率档位（occasionally / often）× 目标距离系数：

| 情境 | 概率 |
|---|---|
| 纯图/表情，上一条是自己，≤3s | 0.6% |
| 纯图/表情，上一条是自己，>3s | 1.4% |
| 纯图/表情，上一条是别人，≤60s | 2.5% |
| 有文字，上一条是自己，≤3s | 1.2% |
| 有文字，上一条是自己，>3s | 7.8% |
| 有文字，上一条是别人，≤50 字 | **20.9%** |
| 有文字，上一条是别人，>50 字 | 8.6% |
| × 目标距离 0 / ≤2 / ≤5 / >5 | 0.5 / 1.0 / 1.1 / 1.5 |

**我们现状**：被 @ 一律引用（`_auto_rid`），其它一律不引用。

**落地**：把「被 @ 必引用」保留，**再加一条**：非 @ 但满足「上一条是别人 + 有文字 + ≤50 字」
时按 20% 概率引用——群里那种「接一句带引用」的感觉就出来了。

## 四、P2：工程层面（可选，收益在可维护性）

| 项 | 它怎么做 | 我们要不要 |
|---|---|---|
| **场景分离** | `scenes/group/{behavior,scheduling,mentions,prompting,quoting,memory}.py`，群/私聊各一套 | 值得：我们 `chat/__init__.py` 6400 行，群/私聊分支交织 |
| **Prompt 目录化** | `prompts/{locale}/main|instructions/{planner,reply,memory,media,learning}/`，带版本覆盖 | 值得：把人格卡/协议拆成可单独编辑的片段 |
| **记忆诊断** | `logs/memory_diagnostics/memory.jsonl`，只记指标不记正文，tracemalloc 深度模式 | 可选：我们有 `/记忆体检`，但没有时间序列 |
| **工具结果压缩** | `tool_result_condenser.py`：长工具结果进上下文前先压 | 值得：我们有 B 站字幕/网页正文这类超长工具结果 |
| **并发闸门** | 学习任务同群互斥 + 全局上限 | 值得：以后加自动学习必须防重复扣费 |

## 五、明确不建议抄

- **A_memorix（3.6MB）**：图数据库式长期记忆 + 去重投影。我们 `memory_v2 + lorebook` 够用，
  迁移成本和收益不成正比。
- **dashboard（521 个 tsx）**：它的 WebUI 是完整前端工程，我们只需要 QQ 里能自检。
- **plugin_runtime / plugin_market**：一整套插件协议 + 市场。我们吃 nonebot 生态就行。
- **多语言 prompt（中/英/日）**：只维护中文，别给自己加三倍工作量。
- **它的工具式 Planner（reply/wait 工具调用）**：我们是 `[[CALL]]` 标记流，
  整体换掉风险大；只抄「正文补动作」那一步就够。

## 六、建议的落地顺序（按性价比）

| 顺序 | 做什么 | 改动量 | 收益 |
|---|---|---|---|
| 1 | **防抖 profiles**（裸图 4s / @ 1s / 整批 8s） | 30 行 | 直接消掉「图还没加载出来」这类时序 bug |
| 2 | **查看频率**（衰减 1/16 + 恢复 16 次） | 40 行 | 插话从「随机」变成「有惯性」 |
| 3 | **静默唤醒**（按平均间隔预测） | 40 行 | 群里刚安静时她会补一句，而不是干等 15s tick |
| 4 | **注意力漂移档位**（纯 prompt） | 文案 | 立刻更像人，零风险 |
| 5 | **引用概率**（非 @ 也有 20% 引用） | 20 行 | 群聊观感明显 |
| 6 | **5 类状态压缩** | 150 行 | 长对话/跨天接得上 |
| 7 | **表达学习（轻量版）** | 200 行 | 学本群口癖，长期收益最大 |
| 8 | **黑话自动挖掘** | 200 行 | 补 lorebook 的自动入口 |

前 5 项加起来不到 200 行，且互不依赖，可以分开发布、单独回滚。

### 和原有设计的关系（重要）

- **防抖**：`MERGE_WINDOW` 保留做底，只在特殊情况下加长/缩短，不改变原有合并逻辑；
- **查看频率**：叠加在原有 `decide_group_reply`（冷却/额度/心情）**之后**，
  不替换它——原闸门决定"能不能说"，查看频率决定"这会儿想不想说"；
- **静默唤醒**：只对「这段对话已经看过、但安静下来了」的情况补一次机会，
  不影响正常的"有新消息就判定"；
- **注意力漂移**：新增一节 prompt，不改动任何硬规则（`_post_rules` 里"只接一个线程"照旧）；
- **对话状态**：最近 N 条原文、词条 lorebook、每日总结全部保留，
  它只是**在历史块前面多一段"更早的对话压成了什么"**，且没数据时不注入。
