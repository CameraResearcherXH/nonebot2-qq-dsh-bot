## C. 「叫她」被理解错（命令/称呼）

### C1（确证）「查看档案」她装死

11:25–11:27 群 100000016 有 **4 次**「查看档案」，她的回复只有：

```
[[THINK|又是查档案，我成查询机了]]
```

**没有任何正文、没有卡片。**

原因链：
1. `查看档案` 不是 `/` 命令（要 `/档案`），所以命令层不接；
2. 聊天层看到这句话，模型知道「要查档案」，但 `profile_card` 工具**要求指定是谁**，
   群友没说查谁 → 模型不知道查谁 → 选择沉默。

→ 群友体感：「说了查看档案，她装死。」

## E. 下次避免：三层方案

### 第 1 层：prompt（最便宜，今天能上，0 风险）

1. **引用约束**：`<reply:>` 只能写**本段** `#` 后面的数字；更早的消息用名字提，不要引用。
2. **插话约束**：没有 ⭐ 时，只接**最后 2 条**内的话题；最后 2 条是图片/表情，就当话题断了，别硬接旧的。
3. **人称约束**：没有 ⭐ 时不要用「你」，用「他/她/名字」；只有 ⭐ 行才能用「你」。
4. **档案**：群友说「查看档案/我的档案」且没指定人 → 查**说话人自己**（speaker_qq）。

### 第 2 层：代码（小改，可回归测试）

5. **插话段裁短**：`addressed=False` 时，投喂给模型的行数 13 → 5（`segments.py` / chat 组装处）。
   现在 76/204 条回复的上下文 ≤3 行，说明段本来就短；但长段插话更容易接旧话题。
6. **昵称加引号**：名字里含「你/我/他/她/咱/大家」→ 渲染成 `「我的床会长猫」(2241706512)`，
   和普通名字区分开，模型不会把昵称当句子。
7. **（可选）插话前先判「有没有人接我」**：无⭐ 且最近 2 条都是别人互聊 → 提高插话门槛（已有 attention/quiet 机制，可复用）。

### 第 3 层：命令层（产品决定）

8. `查看档案` / `看档案` / `我的档案` 加进 `/档案` 的 `aliases`（nonebot 原生支持）；
   或做「无斜杠命令词 → 命令」的映射表（`cmd_guard` 已有类似能力）。
9. 注意：加别名会让这些词**不再进聊天**，她就不能拿它们开玩笑 —— 属于产品口味取舍。
