```
├─ prompt_builder.build_packet

│    │      ├─ 心情：judge.word + judge.value（judge 超过 600s 就退回 label）
│    │      ├─ 你自己写的感觉：label（TTL 12h）

│    │      ├─ 刚刚群里在聊：group_scene 总结
│    │      └─ 你对{X}的好感：affinity ±0.xx（平稳/回暖/在掉）   ← **好感在这里，是个数字**
```

## 3. 对照你的四条澄清

### 3.1 「人 vs 环境」——你说得对，而且代码已经这么做了；我上一版看浅了

我上一版写「心情按会话不按人 = 偏离」，把它当成缺陷。**这个判断不准确**。代码里其实是两层：

```
环境（群 gid）                          人（qq）
├─ mood[group_gid]  现在进行时          ├─ affinity[qq]       长期底色（判读累积）
│   value / label / judge               ├─ affinity_log[]     每次事件（可回溯）
├─ 安静 groups[gid]                     ├─ bond.notes[]       带情绪的事件（60d TTL）
└─ quiet_advisor 对群信号               ├─ 心情归因流水 about_qq（窗口内"因为他掉了多少"）
                                        └─ 安静 users[qq]
```

- **人让她难受** → `affinity` 掉 + `log_shift(about_qq)` 留痕 → `quiet_advisor._person_signal` 建议"对他安静" → `chat_switch.set_off("人", qq, strict=True)`；
- **环境让她难受** → `mood[group]` 掉 + `_group_signal`（群心情 + 难插入）→ 建议"整群安静"。

**这条链路是通的，设计已经落地。** 真正缺的只有两点：

1. **缺"对人的此刻心情"的文字**：现在只有 `affinity`（长期）+ `about_qq` 的 delta 流水（窗口），
   没有一个像 `status_block` 那样的"我现在对他是什么感觉"。
2. **`users` 桶是全局的**：`set_off("人", qq)` 写 `users[qq]`，她在 A 群不理这个人，B 群也不理。
   如果你要的是"只在这个群不理他"，键要变成 `gid:qq`（这是决策点 D1）。

### 3.2 「动态好感」——概念是对的，问题是"速率校准"，不是"要不要动"

你说"好感可以加减、由心情 LLM 判断、人际关系有熟悉和疏离"——代码就是这么写的（`bump_affinity` 每次 ±0.10）。
真正的问题在**速率**：

```
judge 最快 20s 一次 → 一人一小时最多 180 次判读
每次 ±0.10 → 理论上 ±18/小时
而 affinity 无衰减、无日上限 → 20 分钟就能 0 → +1.0 并永久停在 +1.0
```

也就是说：**活跃群里，好感 = 最近 20 分钟的判读累积；安静群里，好感 = 永久判决。**
这既不是"熟悉"，也不是"疏离"，而是"最近谁话多谁好感高"。

建议（三选一，见 §6 D3）：

- **A（推荐）事件化**：`|affinity| < 0.02` 视为噪音丢弃；同一人 10 分钟内只累加一次（取绝对值最大）；每日净变化封顶 ±0.15。
- **B 慢回归**：每天向 0 回归 0.005（+1.0 约 200 天回到 0），模拟"久不联系自然疏远"。
- **C 不改**：接受"话多的人好感涨得快"。

注意：`intimacy` 已经有 30 天半衰（熟不熟会自然降温），所以"疏离"其实已经在 `intimacy` 层实现了。
**不建议把 affinity 也做成半衰**，否则两个层会重复衰减，最后谁都不准。

### 3.3 「好感文字化」——这是最值得做的一件事，而且不需要多调一次 LLM

你要的是：她读了档案/过往，就带着一种"底色"说话。现在 prompt 里只有
`你对阿明的好感：+0.42（回暖）` 这一行数字，模型拿到数字不会自动变成态度。

**建议新增一个 `relation` 块**（和 `mood` 平级，紧跟在 `focus_card` 后面，离当前消息最近）：

```
▍你对阿明的底色（长期，不是此刻心情）
· 好感 +0.42｜亲近 0.58（熟人）｜最近在回暖（3 次 +0.08）
· 想起他，先想到：💛 半夜陪你改代码到三点  💗 记得你不吃香菜
· 也记着：💢 上周说你「烦」，你冷了半晚
· 跟他说话时：放松、愿意多接两句；被戳到会立刻收，不会当场翻脸
```

生成规则（**纯模板 + 现有数据，零额外 LLM 调用**）：

| 段 | 数据来源 | 规则 |
|---|---|---|
| 好感 + 亲近 + 走势 | `get_affinity` / `intimacy` / `affinity_trend` | 5 档文案（厌恶/不待见/平淡/有好感/很喜欢）+ 走势（回暖/在掉/平稳） |
| 正面的事 1~2 条 | `bond.notes` 里 `emotion ∈ {happy, excited, love, touched}`，按 `weight×recency` 排序 | 最多 2 条，每条 ≤28 字 |
| 负面的事 0~1 条 | `emotion ∈ {angry, annoyed, sad}` | 最多 1 条（多了变翻旧账） |
| 跟他说话时的倾向 | 由 5 档映射 | 固定句式，不编 |
| 兜底 | 好感≈0 且无 notes | 返回 `""`，不占 prompt |

**注入规则**（很重要）：
- 只对「当前说话人」和「本条 @/引用的人」注入，**不要给全群每个人**；
- 预算 260~320 字，单独一块（`mood` 已经 460 字，别再挤）；
- 加一条规则：「底色决定你**愿不愿意理他 / 多放松**；此刻心情决定你**这一句怎么说**。
  冲突时以此刻语气为主，但不要因为此刻心情就否定底色。」

这样"看到他就想起开心的事"就真的进 prompt 了 —— 不是靠检索，而是靠**档案里已经存着的事件**。

### 3.4 「空闲衰减」——你的方案是对的，但要注意三个坑

你的设计：有人聊天 → 心思扑在聊天上，由对话驱动；没人聊天 → 安静状态慢慢归 0，负数上涨、正数下降，每 5 分钟 ±0.01。

**先确认单位**（这是最容易搞错的地方）：

- 内部值是 -100~100。若"0.01"指 **-1~1 口径**（= 内部 1 点）/5 分钟：
  | 当前 | 回到 0 需要 |
  |---|---|
  | ±20 | 100 分钟 |
  | ±40 | 3.3 小时 |
  | ±60 | 5 小时 |
  | ±80 | 6.7 小时 |
  | ±100 | 8.3 小时 |
- 若"0.01"指**内部 0.01 点**/5 分钟 → 慢 100 倍（±50 要 17 天），基本等于不衰减。

所以建议按**前者**实现，参数化成 `MOOD_IDLE_STEP=1.0`（内部点）/ `MOOD_IDLE_TICK=300s`。

**算法（lazy，不跑定时器）**：

```
每个 session 增加 last_active_at（真人消息进入时刷新）

def tick(rec, now):
    idle = now - rec.last_active_at
    if idle <= IDLE_AFTER:            # 建议 600s：刚聊完不衰减
        return rec
    steps = int((now - rec.last_decay_at) / TICK)
    if steps <= 0:
        return rec
    for _ in range(steps):
        v = rec.value
        rec.value = v - sign(v) * min(abs(v), STEP)   # 不跨 0
    rec.last_decay_at += steps * TICK
    if abs(rec.value) < 3:            # 数值归零 → 文案也归零
        rec.label = ""; rec.judge = {}
    return rec
```

**三个坑（必须一起处理，否则会互相打架）**：

1. **和现有 12h 半衰期叠加**：`get_mood` 每次读都套 `_decay`（指数），再加线性步进 = 双重衰减。
   建议：`_decay` 只保留给 `global`（或改成 72h 的极慢基线），session 走 idle 步进。
2. **数值归零但文案还挂着**：`status_block` 优先用 `judge`（600s 内），过期后退回 `label`（12h）。
   如果只衰减 `value`，她会"数值已经 0，但嘴上还说两小时前那句'有点烦'"。
   → 归零时同步清 `label` / `judge`（上面伪代码最后一行）。
3. **`get_mood` 是读接口却写盘，且每轮被调 3~5 次**（`status_block` / `mood_factors` / `quiet_advisor`）。
   加衰减会放大写盘。建议顺手改成"有变化才写 + 进程内缓存（mtime 失效）"，和 `chat_switch._load` 一样的做法。

**"有人聊天"的判定口径**：建议**按会话**（每个群/每个私聊各自 `last_active_at`），
它天然覆盖你说的"所有会话都没人找她"；而且比全局判定更准 ——
A 群热闹不代表 B 群的心情不该冷下来。

## 4. 一个必须先补的缺口：记忆没有"正负号"

"看到他就想起**开心**的事"要求记忆能区分**开心**和**痛苦**。但：

```python
memory_v2.remember(..., emotion_hit=True, emotion_weight=0.8, mood_value=0.42)
#                         ↑有没有情绪        ↑多强            ↑只有判读新鲜时才有
```

- `emotion_hit` 只说明"有情绪"，`emotion_weight` 只说明"多强"，**都没有正负**；
- `mood_value` 是最近才加的，只对"判读新鲜"的记忆有效，2383 条存量里大部分没有；
- 全项目 grep 不到 `valence`。

所以现在能可靠区分正负的只有 **bond notes**（带 `emotion`，但上限 20 条、60 天 TTL）。
这就是为什么 §3.3 的文字块建议**先用 bond** —— 它能马上用；长期要靠给 memory 补 `valence`。

建议（D6）：`remember()` 增加 `valence: -1..1`，写入时从 `emotion`（或 `judge.value`）推导；
索引加 `(about_qq, valence)`，这样"按人 + 按正负"检索才成立。

# 8. 记录模型 v2：阈值驱动的显著性（统一 memory / bond / sticker）

> 来源：用户 2026-11-20 第二轮补充。
> 原话要点：「三方 llm 已经生成阈值了，所以记忆刻痕也该从文字变成阈值。
> 忽然某件事阈值变化了一大截，肯定印象深刻 → 记录；变化极小 0.01 就不容易记住，
> 对应人对不在意的事不上心。心情名词用三方 llm 总结的名词；心理活动用事情返回的心理活动。
> 于是变成：时间 / 心情名词 / 阈值（决定记录、加粗、查找优先级）/ 事情总结（目录）/
> 心理活动 + 事情详细（内容）。表情包同理：看到图 → llm 判心情阈值 → 大涨就收 → 名词当标签。」

## 8.1 先把三个词定死（否则代码里会继续混）

| 词 | 定义 | 量纲 | 来源 |
|---|---|---|---|
| **心情值 level** | 她此刻的心情 | -1.00 ~ +1.00（内部 ×100） | `judge.value` |
| **变化量 delta** | 这件事让心情值变了多少 = 本轮 value − 上轮 value | -2.00 ~ +2.00 | 本地相减（不需要判读再输出） |
| **显著性 salience** | 这件事有多值得记 = \|delta\| 归一化 | 0 ~ 1 | `min(1, abs(delta)/0.5)` |

**关键收益**：`delta` 的**符号**就是 valence（正=开心的事，负=难受的事），
`abs(delta)` 就是 salience（强度）。上一轮说的「记忆没有正负号」这个缺口，
用 delta 一次性解决 —— 不需要再单独设计 valence 字段。

## 8.2 统一记录结构（memory / bond 共用）

```python
record = {
  "id":         "...",
  "ts":         1732000000.0,
  "session":    "group_[REDACTED_NUMBER]",      # 哪段对话
  "gid":        "[REDACTED_NUMBER]",
  "about_qq":   "10001",                # 关于谁
```

## 8.3 二维模型：时间 × 情绪（**Δ 不是"记不记"的开关**）

用户 2026-11-20 第四轮更正：

> 「记忆是二个维度的：近期事情到远期事情，情绪波动大到小。
>   是都要记，而近期事情记得清、容易查，遥远记忆不容易查；
>   情绪波动大的容易查，情绪波动小的不容易查。
>   等于说记忆是目录和展开目录的详细，目录是总结事情，从近到远动态往后累积。
>   而情绪波动相当于是否要加粗目录。」

正确模型：

```
                情绪波动大
                    ▲
        💥💥💥       │       💥💥💥
     远期·高情绪     │    近期·高情绪        ← 都容易查
                    │
  ──────────────────┼──────────────────► 时间（近 → 远）
                    │
      远期·低情绪    │    近期·低情绪
       （最难查）     │    （好查，但不显眼）
                    ▼
                情绪波动小
```

| 维度 | 作用 | 代码 |
|---|---|---|
| 时间（近→远） | 决定"记得清不清 / 好不好查" | `created_at` + `last_hit_at` + `_forget_factor`（30~90 天 τ） |
| 情绪（大→小） | 决定"加不加粗 / 检索加成 / 遗忘快慢" | `salience` → `emotion_mark` + `w_emo` + τ 加长 |

**记录层（记忆全记，档案只记影响好感的事件）**：
- **记忆：每个 turn 一条目录项，全记**（不按 Δ 筛，见 §8.8）；
- **档案：只记 `cause=speaker` 且 \|Δaff\| ≥ 0.01 的事件**（好感涨落的原因）；
- `fact / call / agreement`：进记忆，永远记；
- **Δ 不作为"记不记"的门槛**（上一版写的「<0.03 不写」是错的，已删）。

**目录层（从近到远累积）**：
- 目录项 = 时间 + 心情名词 + 💥 标记 + 事情总结（title）；
- 默认按**时间倒序**（最近的在前），不是按相关度；
- 点开 = 心理活动（mind）+ 事情详细（detail）。

**检索层（两维决定难度）**：
- 近期 + 高 |Δ| → 最容易查到；
- 远期 + 低 |Δ| → 最难查到；
- 关键词只是"额外加分"，**不能当硬门槛**（见 §8.3b）。

事件类呈现分级（`salience = min(1, |Δ|/0.5)`）：

| \|Δ\| | salience | 记录 | 加粗 | 检索权重 | 遗忘 τ |
|---|---|---|---|---|---|
| < 0.03 | < 0.06 | **照记** | 无 | ×0.8 | 30 天 |
| 0.03 ~ 0.10 | 0.06 ~ 0.2 | 照记 | 无 | ×1.0 | 30 天 |
| 0.10 ~ 0.25 | 0.2 ~ 0.5 | 照记 | 💥 | ×1.2 | 45 天 |
| 0.25 ~ 0.50 | 0.5 ~ 0.8 | 照记 | 💥💥 | ×1.8 | 60 天 |
| ≥ 0.50 | 1.0 | 照记 | 💥💥💥 | ×2.5 | 90 天 |

标记阈值可以直接复用现有 `_EMO_MARKS = ((0.8,"💥💥💥"),(0.5,"💥💥"),(0.2,"💥"))`（memory_v2:259），
把输入从 `emotion_weight` 换成 `salience` 即可，展示层零改动。

### 8.3b 现有代码离这个模型只差一步

`memory_v2.recall` 的公式**已经是二维的**：

```python
score = bm25 × w_speaker × w_imp × w_emo × w_forget
#                 w_emo = 1 + 2.5*salience     （情绪维度）
#                 w_forget = exp(-days/τ)       （时间维度）
```

问题只有一个：**BM25 被当成了硬门槛**。

```python
base = bm25.get(d["id"], 0.0)
if base <= 0 and d["importance"] < 0.7:
    continue          # ← 近期但没词重合的普通事，永远进不了目录
```

所以「近期事情记得清」这条其实**没有实现**：一句「在吗」召不出「昨天他说的那件事」。
建议把 BM25 从"门槛"降级为"加分"：

```python
score = (0.15 + bm25_norm) × w_speaker × w_imp × w_emo × w_forget
```

这样：近期 + 高情绪的记忆，即使当前这句话没有关键词重合，也能被召出来；
远期 + 低情绪的记忆，仍然会沉底（`w_forget` 自然把它压下去）。

另外 `recall_catalog`（memory_v2:426）默认是**相关度排序**，应按你的模型改成：
- 默认（不带关键词/时间）→ **时间倒序**（从近到远）；
- 带关键词 → 相关度；
- 带时间 → 时间倒序。

## 8.4 写入时序：现在用的是「上一轮」的判读值（这是真 bug）

`plugins/chat/__init__.py` 里的顺序是：

```
4035  _spawn_mood_judge(...)        ← create_task，异步，还没跑
4087  _jd = mood.get_judge(key)     ← 读到的是**上一轮**的判读
4130  emotion_weight = abs(_jv)     ← 用上一轮的心情"绝对值"，不是本轮的 |Δ|
```

所以现在记忆的「刻痕强度」既不及时（慢一轮），也不是变化量（是水平值）。
你要的「这件事让阈值变了一大截」在数据上**根本没有被算出来过**。

推荐写法（不增加延迟、不丢事件）：

```
回复生成 → parse → 立即写 memory（status=pending, turn_id=session:mid）
                    ↓（后台判读完成）
        judge 算出 delta = new_value - prev_value
                    ↓
        memory_v2.patch_salience(turn_id, delta, mood_word, mind)
                    ↓
        status=active（Δ 只写 salience / 加粗 / 检索权重，**不决定是否归档**）
```

- 判读失败 → 保留写记忆时的兜底 salience（用 `memo.importance` 或 emotion 表），**记忆不丢**；
- `turn_id` 用 `f"{session_key}:{message_id}"`，天然幂等；
- 这样「事情详细」先落盘，「显著性」后补，符合「先记录、后加权」。

## 8.5 自动记录：高 |Δ| 但她没写 MEMO

她的 MEMO 是「真的触动才写」，命中率不高（真机 2/7）。
你的设计里「变化了一大截 → 肯定印象深刻 → 记录」意味着**系统要能自己补记**：

```
if |Δ| >= AUTO_RECORD_DELTA (建议 0.25) and 本轮没有 MEMO:
    自动记一条 event：
      title  = judge.src（最后一条真人消息，≤30 字）
      detail = judge.why + "；" + judge.mind
      mind   = judge.mind
      mood_word = judge.word
      delta  = Δ
      about_qq = speaker_qq
    每轮最多 1 条；同 session 10 分钟内不重复
```

这条是「互补」的核心：**她负责主观觉得值得记，系统负责客观变化大的**。
两边都记，但用同一个 salience 排序，不会变成两套记忆。

## 8.8 记忆 vs 档案：两种记录策略

用户 2026-11-20 第五轮明确：

> 「永远进目录。但是在记忆查询优先级上做区分，我们记录的时候记录分先后，
>   情绪刻痕决定加粗（更容易找）。但是档案只记录彼此之间的导致好感涨落的事件，
>   不是每条都记。而记忆是全记，但是查询方法我们有优化而已，类似于更容易想起来哪些事。」

| | 记忆（memory） | 档案（profile / bond） |
|---|---|---|
| 记什么 | **全记**：每个 turn 一条目录项 | **只记影响好感的事件**（`cause=speaker` 且 \|Δaff\| ≥ 0.01） |
| 排序 | 时间倒序（从近到远） | `weight` / salience + 时间 |
| 情绪作用 | 加粗 + 检索加成 + 减慢遗忘 | `weight = 1 + 2*salience` |
| 用途 | 「我经历过什么」 | 「我跟他是什么关系」 |
| 展开 | mind + `dialogue_log` 原文 | text + mood_word + mind |

推论：

- `add_bond_note` 只在 `|Δaff| ≥ BOND_MIN (0.01)` 时调用（现在是每条 MEMO 都写）；
- 中性相处经历（`kind:bond` 但没有好感变化）**只进记忆，不进档案**；
- 档案卡的「事情」= 影响过关系的事；「最近的事」应从记忆目录按 `about_qq` 取，两者不要混。

# 11. 收口：一个 Δ，三处用（2026-11-20 第三轮补充）

> 用户原话：「甚至忽然心情的波动本身就能映射好感的增减幅度。」

这句话把整套设计收口了。现在 `mood_judge` 同时输出 `value`（心情）和 `affinity`（好感增量），
两个字段互相独立 —— 于是会出现「心情 +0.5，好感 −0.08」这种自相矛盾。
按你的思路，**好感增量不该是第二个判读结果，而应该由心情波动推导**：

```
                      Δmood = value − prev_value   （带符号，-2.00 ~ +2.00）
                     /                |                \
              |Δmood|            sign(Δmood)       Δmood × gain × cause
                ↓                    ↓                     ↓
            salience              valence              Δaffinity
      （加粗/检索/遗忘）     （开心的事 / 难受的事）   （好感增减幅度）
```

同一个 Δ，同时决定：**这条记忆值不值得记**、**它是好是坏**、**对这个人好感涨多少**。
这就是你说的「互补」—— 不需要三套判据，也不需要再单独设计 valence。

## 11.1 必须先加一个字段：`cause`（否则环境的心情会污染好感）

心情是**会话级**的：群里气氛好、话题好笑，她心情也会涨。
如果直接把 Δmood 映射成好感，那么「群里讲了个笑话」会让**最后说话的那个人**白赚好感 ——
这是现在就已经存在的误归因（`_maybe_mood_watch` 给每条消息都带 `speaker_qq`），
只是现在每次只有 ±0.10，不明显；一旦按 Δ 映射，误差会被放大。

所以判读输出要从 5 字段改成 6 字段：

```
{"mind": "...", "word": "...", "value": 0.42, "cause": "speaker", "why": "..."}

cause 取值：
  speaker      是正在说话这个人让她心情变化的（夸、骂、逗、哄、无视）
  environment  群里的气氛/话题/别人，不是针对她（大家在讲笑话、在吵架）
  self         她自己的事（想起以前、困了、身体不舒服）
  other        群里另一个人（不是当前说话人）
```

映射规则（**注意：不是纯函数映射**，见 11.1b）：

```python
Δmood = value - prev_value
valence  = sign(Δmood)                          # 正=开心的事 / 负=难受的事

# ① 记忆：Δ **不决定记不记**，只决定"加不加粗 / 好不好查"
salience = min(1.0, abs(Δmood) / 0.5)           # 写进索引，供加粗 + 检索加成 + 减慢遗忘
# 记录由别的条件决定：她写了 MEMO / 高 Δ 系统补记 / fact·call 永远记

# ② 好感：个人导致的心情变化，大起大落和小涨落都要记（这是"记录"，不是"筛选"）
if cause == "speaker" and abs(Δmood) >= AFF_MIN (0.005):
    Δaff = clamp(Δmood * AFFINITY_GAIN * tol, -CAP_NEG, +CAP_POS)
    # tol = 忍耐系数：本来好感高/亲近，同样的 Δ 扣得少一点（沿用 quiet_advisor 的思路）
else:
    Δaff = 0                                    # 环境/自己/别人引起的心情，不动好感
if repair:                                      # 他道歉/哄她：至少回暖一点
    Δaff = max(Δaff, +0.03)
```

**这一步同时修掉了一个现存的误归因 bug**：环境让心情涨，不再算到某个人头上。

### 11.1b 为什么不是「完全映射」

用户 2026-11-20 第三轮补充原话：

> 「当然不能完全映射好感，好感是因为某个个人忽然大涨或者大降的心情记录，或者是小涨落。
>   我的意思是个人导致的心情变化很容易来决定好感的涨落。」

拆成三条规则：

1. **只认「个人导致」**：`cause=speaker` 才动好感；环境/自己/别人引起的心情变化不进好感。
2. **大起大落和小涨落都算，但表现不同**：
   - 大起大落 → 高 salience → 记忆目录里加粗、优先召回；好感一次明显变化；
   - 小涨落 → 记忆里照记（只是不加粗、容易沉底），好感也照样累加（gain 小）。
     人际关系就是被很多「不值一提的小事」慢慢推着走的。
3. **不是 1:1**：还要叠加
   - `tol` 忍耐（本来好感高，同样的冒犯扣得少）；
   - 单次上下限、每日净变化上限（防 20 分钟饱和）；
   - 慢回归（久不联系自然疏远）；
   - 非心情因素（`profile_update` 写进来的稳定印象、`fact` 类事件）。

用公式表达：

```
affinity(t) = affinity(t-1)
            + Σ 个人导致的 Δmood × gain × tol      # 主驱动
            + Σ 非心情事件（profile_update / 明确印象）  # 次驱动
            - 慢回归（无互动天数）
```

**存储上要区分两种流水**（现在只有一个 `affinity_log` 保留 50 条，小涨落会把它冲掉）：

```
affinity_log[]    最近 50 条「显著事件」（|Δaff| ≥ 0.02），给 /档案 和 relation 块看
affinity_daily{}  按天聚合的净变化（保留 365 天），给趋势/回归/周报用
```

这样「小涨落」不会丢，也不会把 50 条日志挤爆。

## 11.2 映射系数（防止 20 分钟饱和 / 死亡螺旋）

`AFFINITY_GAIN` 建议 **0.05 ~ 0.08**，单次封顶 `+0.08 / −0.06`（负向略小，防死亡螺旋）：

| Δmood | Δaff（gain=0.05） | 含义 |
|---|---|---|
| 0.05 | +0.0025 | 噪音，忽略 |
| 0.20 | +0.010 | 一点好感 |
| 0.50 | +0.025 | 明显好感 |
| 1.00 | +0.050 | 很戳 |
| 2.00 | +0.080（cap） | 从极差到极好，一次封顶 |

按这个系数，**从 0 到 +1.0 需要约 20 次「Δmood=1.0」的大事件**，
再叠加每日上限 ±0.15（D3），至少跨 7 天 —— 这才像「关系」，而不是「话多就涨」。

⚠️ 两个反向风险要一起考虑：

1. **负向死亡螺旋**：被骂 → 心情掉 → 好感掉 → 更冷 → 对方更烦 → 心情更掉。
   → 负向系数打折（×0.75）+ 破冰修复（道歉至少 +0.03）+ `quiet_advisor` 的忍耐项。
2. **正向棘轮**：一直开心 → 好感顶满 → 不再变化。
   → 靠 D2（慢回归）+ 心情饱和时 Δ≈0（自然停止增长）两个机制共同兜住。

## 11.3 判读输出字段的最终形态

```json
{
  "mind":  "嘴上不认，其实挺受用",
  "word":  "被夸得有点飘",
  "value": 0.42,
  "cause": "speaker",
  "why":   "他夸了她，她装没事"

```

- `affinity` 字段**删掉**（由 Δmood 推导），少一个自相矛盾的来源；
- `value` 仍是「此刻心情值」；`prev_value` 由调用方传（判读 prompt 已经在传）；
- `cause` 是新增，也是这次收口最关键的一个字段。

## 11.4 连带改动（都在同一处写入路径上）

```
mood_judge.judge_and_store()
  ├─ Δmood = value - prev_value

  └─ mood.set_value_from_judge(value)
```

# 13. 实现口径（2026-11-20 最终定稿，代码已按此实现）

## 13.1 判读模型给的是「涨幅 Δ」，不是当前心情值

```
判读输出：{mind, word, delta, cause, why, bond_word?}
  · delta     —— 这件事让她心情**涨/跌了多少**（-1.00~+1.00）
                正 = 变好，负 = 变差；不是"她现在什么心情"
  · word      —— **这件事的反应词**（"被夸得有点飘"），只用于记忆/档案记录
  · bond_word —— 参考档案给的「她怎么看他」的描述性说法（4~10 字），可省略
```

当前心情值是**一个持续累加的变量**（-1~1），由系统维护：

```
心情值 ← clamp(心情值 + Δ, -1, 1)
```

- 作用域：`MOOD_SCOPE=session`（默认，每个群/私聊各一个）或 `global`（全机器人共用一个）
- 单次涨幅上限：`MOOD_MAX_DELTA=0.50`（防止模型一次给极端值）
- 空闲衰减：`MOOD_IDLE_AFTER=600s` 后每 `MOOD_IDLE_TICK=300s` 向 0 走 `MOOD_IDLE_STEP=1.0`（内部点）

## 13.2 心情名词 = 数值分档（每 0.2 一个词）

| 区间 | 名词 |
|---|---|
| [-1.0, -0.8) | 被击穿 |
| [-0.8, -0.6) | 很难受 |
| [-0.6, -0.4) | 憋着一口气 |
| [-0.4, -0.2) | 有点扫兴 |
| [-0.2, 0.0) | 淡淡的 |
| [0.0, 0.2) | 平平的 |
| [0.2, 0.4) | 有点高兴 |
| [0.4, 0.6) | 心情不错 |
| [0.6, 0.8) | 挺开心 |
| [0.8, 1.0] | 特别好 |

模型给的 `word` 不再当心情名词，而是作为「刚才那下：<反应词>」单独一行。

## 13.3 一个 Δ 三处用

| 用途 | 计算 | 落到哪 |
|---|---|---|
| 记忆刻痕 | `salience = min(1, |Δ|/0.5)` | `memory_v2` 的 `delta/salience/valence`（json 与 sqlite 都写） |
| 正负 | `valence = sign(Δ)` | 同上 |
| 好感 | `Δ × AFFINITY_GAIN`，单次 +0.08/−0.06，`cause=speaker` 才算 | `profiles.bump_affinity`（每日净变化 ≤ `AFFINITY_DAILY_CAP=0.15`） |

**明确不用「当前心情水平」算任何东西**：不因为"我现在很开心"就觉得"你特别好"，也不因为"我现在很开心"就"这条记忆很重要"。

## 13.4 好感名词（bond_word）

判读时把档案摘要（好感数值 / 亲近度 / 最近两条相处印象）一起给模型，
让它给一个 4~10 字的描述性说法，写进 `profiles.set_bond_word()`，
在 `relation_block` 里渲染成「你眼里他：又爱又嫌的老熟人」。

## 13.5 表情包

视觉侧输出三行：`反应 / 强度 / 描述`。

- `强度` = **这张图让她变化多大**（和当前心情无关），`|强度| ≥ STICKER_COLLECT_MIN(0.25)` 才收；
- 收下时把 `reaction`（强度）存进表情库，标签用「反应词」，不用"我心情如何"。

## 13.6 现在进行时用在哪

- `mood.status_block()` → 心情名词（分档）+ 数值 + 「刚才那下」+ 心里话
- `profiles.relation_block()` → 好感数值 + 好感名词 + 亲近度 + 1~2 条正面事
- 两者一起进 prompt：**底色决定愿不愿意理他，此刻决定这一句怎么说**

## 14. 峰值事件与「印象最深的一件事」（2026-11-20）

### 14.1 心情峰值事件：抵消 + 2 小时保质期

用户原话：「显示最近一件涨降幅度最大的一件事和心理活动。比如 -0.38 很伤心，
后面 +0.18、+0.22 已经把它抵掉了，这个 -0.38 就不再是最大值，砍掉去换下一个
最大值。2 小时内没抵消就自动过滤掉 2 小时之前的增减 —— 每件事最多挂两个小时。」

实现：`services/mood.py::peak_event(session_key)`

1. 取最近 `MOOD_PEAK_WINDOW_SEC`（默认 7200 = 2 小时）内、本会话的所有 Δ；
2. 忽略 `|Δ| < MOOD_PEAK_MIN_DELTA`（0.03）的闲聊；
3. 选 `|Δ|` 最大的一件事；
4. 看它**之后**的反向 Δ 能不能把它抵消（例：-0.38 后面 +0.18 +0.22）；
   - 能抵消 → 这件事和用掉的反向事件一起从候选里去掉，回到第 3 步换下一个最大值；
   - 不能抵消 → 它就是「峰值事件」；
5. 超过 2 小时的事件自动不参与（每件事最多挂 2 小时）。

渲染（`status_block`）：
- 方向一致：`最近最让你开心的一件事：…（当时你心里：…）`
- 当前心情是正的、峰值是伤心事：`你现在的心情状态是：<名词>，但是呢你最近经历了一件不愉快的事：…`
- 当前心情是负的、峰值是开心事：`你现在的心情状态是：<名词>，不过呢你最近也遇到一件挺开心的事：…`

### 14.2 好感名词后面补「印象最深的一件事」

`profiles.relation_block()` 在「你眼里他：<bond_word>」下面多一行：

```
· 你与阿明印象最深刻的一件事：他半夜给我送药（当时你心里：鼻子有点酸）
```

来源：`memory_v2.deepest_event(qq)` 取关于这个人 `|Δ|` 最大的记忆
（`BOND_EVENT_MIN_DELTA=0.15`），连判读模型当时的 `mind` 一起给；
记忆里没有才退回档案里权重最高的刻痕。

### 14.3 空闲自减

没人说话时每 5 分钟向 0 走 0.01（`MOOD_IDLE_AFTER=300`、`MOOD_IDLE_TICK=300`、
`MOOD_IDLE_STEP=1.0`）。两个容易写错的地方都已修：

- `_decay()` 必须把 `last_active_at` / `last_decay_at` 带过去，否则 `_idle_decay`
  永远拿 `updated_at(=now)` 判断，自减不生效；
- `touch()` 必须**先结算**沉默期间的步数，再重置计时；否则消息一到就清零，
  之前该走的那几步全被抹掉。

## 15. 群心情：独立于整体心情的一层（2026-11-20）

用户原话：「当前心情 + 人物好感决定是否愿意主动找这个人倾诉/聊天，也决定是否
愿意在这个人面前安静……还要有一个群里多少人喜欢你、多少人讨厌你。这个比例
决定她在群聊里的整体环境，决定是否愿意在群里安静。这个讨厌和喜欢可以通过最近
5 小时在这个群环境里降低/增加多少心情决定。如果是某个人导致的，就单独不理那个
人（包括 @）；如果是三个人及以上导致的，就可以判定是群聊导致的不愉快。
阈值：群连续降低 0.7，个人 0.4。可以被这个群拿到的正值抵消，不是只统计一个方向。
所以这其实是独立于整体的一个群心情波动，5 小时事件超时。」

### 15.1 数据层：`services/group_mood.py`

只记事件流水，快照读取时现算：

```
{"groups": {"<gid>": {"events": [
  {"at":…, "delta":-0.2, "about_qq":"10001", "cause":"speaker",
   "why":"他当众说我笨", "mind":"有点下不来台", "word":"被戳到"}
]}}}
```

- 只有 `group_xxx` 会话才记；
- `cause=speaker` 才记到具体人头上；`environment/other` 只算群环境；
- `cause=self`（她自己的事）不进群心情；
- 窗口 `GROUP_MOOD_WINDOW_SEC=18000`（5 小时），超时事件自动过期；
- 正负值直接相加，所以「后面拿到的正值」能抵消前面的负值。

### 15.2 判定

| 判定 | 条件 |
|---|---|
| 单独不理某个人（含 @） | 这个人 5 小时净跌 ≥ `GROUP_MOOD_PERSON_DROP=0.4` |
| 群聊导致的不愉快 | 整群净跌 ≥ `GROUP_MOOD_GROUP_DROP=0.7` **且** 至少 `GROUP_MOOD_MIN_PEOPLE=3` 个人净跌 |
| 喜欢你 / 讨厌你的人数 | 每个人净 Δ ≥ +0.05 / ≤ -0.05；比例 = 喜欢 ÷ (喜欢+讨厌) |

`chat_factor()` 把群心情换算成「愿不愿意在这个群多说话」的乘数
（`0.55 ~ 1.35`），已接进 `mood.mood_factors()["chatty"]`：
整体心情再好，在一个 5 小时净掉 0.7 的群里也会明显少说话。

### 15.3 接进哪里

- `mood_judge.judge_and_store()`：每次判读把 Δ 写进 `group_mood`；
- `quiet_advisor._person_signal()`：单人净跌 ≥0.4 → 单独不理他；
- `quiet_advisor._group_signal()`：整群净跌 ≥0.7 + 3 人 → 整群安静建议，
  并在依据里写「X 人让你舒服 / Y 人让你不舒服」；
- `mood.mood_factors()`：群心情乘数影响群聊接话概率；
- `proactive.score_of()`：主动私聊加入「对他的好感」（好感 ≤ -0.25 不主动找；
  心情低 + 好感高 → 更想找他倾诉，×1.15）；
- `/测函数 安静` 会打印 `group_mood.status_text()`（净变化 / 喜欢讨厌人数 /
  单人判定 / 整群判定 / 多说话乘数）。
