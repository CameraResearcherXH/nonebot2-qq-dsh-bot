# 判读链路审计：她读到什么 → 她怎么理解 → 判读模型看到什么 → 标成什么

日期：2026-11-25 21:05｜配套：`emotion-annotation-spec.md`、`mood-source-audit-20261125.md`、
`verification-report-20261125-affinity-pipeline.md`

---

## 0. 一句话结论

判读链路**方向是对的**（她自己的 THINK 是唯一标签源），但「她这条在回」这一环以前是
**一坨 200 字截断文本**，判读模型得自己猜哪句触发了她的心理活动；同时**词表标注的召回只有
约 1/4**，`nohit` 里大量是真实情绪。已修输入侧（src 清洗、去重、留痕），标注侧建议改用
「先判评价维度、再算 impact」的两段式，而不是继续扩词表。

---

## 1. 四层链路（现在长什么样）

```text
① 她读到      群聊原文（谁 → 收件人：内容）
② 她理解      [[THINK|…]]  第一人称心理活动      ← 唯一标签源（ADR-038）
③ 判读看到    prompt：她的 THINK + 她这条在回 + 8 条群聊 + 档案 + 上一轮
④ 标成        impact(-2~+2) / cause / target / relation / word / why
```

判断「她有没有理解错」**不在这一层做**：她理解错了也是她的感受，判读只判
「这事是不是冲她说的、她有没有往心里去」；`target` 只回答「关于谁」。

## 2. 真实判读输入：修之前 vs 修之后

### 2.1 修之前（20:57 真机 trace）

```text
【她的心理活动】他在为我费心，有点小高兴
【她这条在回】格林 → 大家：所以天天幻想救赎别人；赖在群友家吃白饭的猫 → 高性能萝卜子～(6441)：
我去，不早说。不找到这样的机器人，我就不死了 〔引用 高性能萝卜子～(6441) 20:57 的消息（只作指代，
回复时不要复述原文）：老了过后亚托莉技术就成熟了；⭐阿明 → 你：躺不了，在给你加标签，防止你
理解接错消息 〔引用 大肥鱼(9194) 20:57 的消息（只作指代，回复时不要复述原文）：一轮微
【最近 8 条群聊】
5. 格林 → 大家: 所以天天幻想救赎别人
6. 格林 → 大家: 所以天天幻想救赎别人      ← 相邻重复
```

问题：

| # | 问题 | 后果 |
|---|---|---|
| 1 | src 是 4 条消息拼成的一坨，**截断在句子中间** | 判读不知道「到底哪句让她高兴」 |
| 2 | src 里带两个 `〔引用…〕` 块（更早的别人的话） | 判读把旧话当成这次的事 |
| 3 | src 和下面 8 条上下文**大段重复** | prompt 浪费、判读分不清主次 |
| 4 | 上下文有**相邻完全重复**的行 | 判读以为「被反复说了」，会加重 impact |

### 2.2 修之后（21:02 真机 trace）

```text
【她的心理活动】这前提比那玩意还贵，他未必不知道
【她这条在回】alpha → 大家：我等下把重新测的结果再发一遍；格林 → 大家：况且我如果有一个爱我的老婆，要这玩意干嘛
```

判读输出：

```json
{"mind":"这前提比那玩意还贵，他未必不懂","word":"心里默默吐槽","impact":0,
 "cause":"environment","why":"格林说要有爱老婆就不要那玩意，她在心里算账吐槽",
 "relation_relevance":0.2,"confidence":0.55}
```

`impact 0 / cause environment` 是对的：她在吐槽别人的话题，不是冲她来的。

## 3. 标签算法：词表的天花板在哪

### 3.1 她的心理活动其实只有约 1/4 带情绪词

`data/mood_think.json`（190 条 `auto=false`）：

| 类型 | 条数 | 占比 |
|---|---|---|
| `emo` 命中情绪词 | 43 | 23% |
| `nohit` 词表没命中 | 140 | 74% |
| `plan` 计划/决策 | 4 | 2% |
| `watch` 观察/疑问 | 3 | 1.5% |

`src` 缺失 5 条、`reply` 缺失 8 条（这些条目判读时没有「她在回什么」，容易记错人）。

### 3.2 `nohit` ≠ 没情绪（这是关键）

抽检 v1 里 `nohit` 但被标了 ±1 的 12 条：

```text
他这么软，我反而不知道该硬哪        → +1（被撩到）
一装可怜我就没辙了                  → +1（心软）
这么直白，我反倒不知道说什么了      → +1（害羞）
明明想收，还非要嘴硬一句            → +1（口是心非）
他这是非要把鱼塞我手里              → -1（被硬塞）
```

这些**都是真实情绪**，只是词表里没有「没辙 / 不知道说什么 / 软 / 嘴硬」这些搭配。
所以：

- v1（逐条判）`nohit` 92 条里 **64 条非零** → 判得对，是词表漏召回；
- v2（词表首标）`nohit` 116 条里只有 **3 条非零** → 词表**精度高、召回低**。

**结论：继续扩词表是走不通的**（中文情绪搭配是长尾）。词表只适合做**抽样分层**，
真正标注要用语义模型（判读 LLM 本身），再用人工抽检校准。

### 3.3 v2 的 69% 非零是抽样放大的，不是真实比例

全量语料 3007 条 THINK，词表命中约 1/4；v2 是**按命中分层抽**的 400 条（-1 138 / 0 120 / +1 137），
所以不能拿 v2 的非零率当「她 69% 的时候有情绪」。

## 4. 论文/案例 → 我们能落地的 4 条优化

| 依据 | 要点 | 对应到我们 |
|---|---|---|
| **评价理论 / OCC**（Ortony–Clore–Collins） | 情绪来自对**事件是否合意**、**他人行为是否可赞**、**对象是否讨喜**的评价 | 判读别直接问「-2~+2」，先问「这事合不合她的意 / 谁做的 / 她在不在意」，再由规则算 impact |
| **VAD 三维模型**（valence–arousal–dominance） | 三个维度独立；a/d 不等于 v | 我们现在 a/d 只记录、不进 v（emotion §1.5）——**这条是对的，别改** |
| **Appraisal 语料标注可靠性**（arXiv 2206.05238） | 评价维度可标注且一致性不错，情绪可由维度推导 | 支持「两段式」：维度标注 → 规则合成 impact，比让模型直接给档位更稳 |
| **自述 vs 旁观者评分**（临床/人格研究一致结论：中度相关、**不可互换**） | 自述和旁观是两种构念 | 支持 ADR-038：**只用她的 THINK**；旁观标签只能当对照，不能当真值 |

### 建议的判读输出（两段式）

```json
{
  "about": "speaker|recipient|other|world|self",   // 这事关于谁（=现在的 target）
  "desirability": -2|-1|0|1|2,                     // 合不合她的意
  "agency": "speaker|other|world|self",            // 谁造成的
  "cared": 0|1|2,                                  // 她在不在意（0=看戏）
  "mind": "…", "word": "…", "why": "…"
}
```

impact 由代码合成：`impact = desirability × cared_weight`，`cared=0 → 0`。
好处：

1. **「看戏」有显式出口**（cared=0），不用靠模型自觉给 0；
2. 「她理解错了」不影响 `desirability`（她按自己理解评的），但 `about` 能标出「其实不是说她」；
3. 三个维度都能单独抽检，比一个 -2~+2 好校准（也更容易算 QWK）。

## 5. 工具逐个看：设计一致性 / 风险 / 建议

> 共 36 个工具（`RET_TOOLS_TOP=6` 按消息相关性取前 6，`send`/`stay_silent` 永远保留）。
> 「与心情的关系」= 这个工具会不会绕过 THINK 改心情/好感。

### 5.1 协议与核心

| 工具 | 作用 | 与心情的关系 | 结论/建议 |
|---|---|---|---|
| `send` | 发工具产出的待发内容 | 无 | ✅ 协议工具，必须留 |
| `stay_silent` | 这轮不说话 | 无（只记原因） | ✅ 正确：**安静不该改心情**，否则「不想说话」会被记成负分 |
| `chat_switch` | 群/个人静音 | 无 | ⚠️ 建议：静音**不写好感**（现在是纯行为），但可以记一条 `mood_events` 方便复盘 |
| `recall` | 查长期记忆 | 无 | ✅ |
| `remember` | 写长期记忆 | 无（`emotion_hit` 只影响显著性） | ✅ 注意：`remember` **不写档案**（上一轮已改），避免和档案重复 |
| `profile_card` | 读档案 | 无 | ✅ |
| `profile_update` | 写身份/性格/称呼/stance/talkativeness | 无（**不能写 affinity/mood**） | ✅ 边界正确；`talkativeness` 建议也由心情派生，别让模型直接设 |
| `set_call` | 称呼 | 无 | ✅ |
| `api_usage` | 用量 | 无 | ✅ |

| `sing` / `song` / `cover` / `rvc` / `tts` / `audio_split` | 语音/唱歌 | 无 | ⚠️ 6 个媒体工具同理，建议 `media` 单入口 + action |
| `vision_source` | 看图 | 无 | ✅ 图片识别结果**不该**直接当情绪依据，只作为 THINK 的上下文 |

### 5.4 自检 / 改代码（高风险）

| 工具 | 作用 | 与心情的关系 | 结论/建议 |
|---|---|---|---|
| `self_tool_file` / `self_tool_write` / `self_tool_run` | 她写工具、跑工具 | 无 | ⚠️ 默认 `private,group`，靠 `SELF_TOOL_OWNER_ONLY=true` 挡非主人。建议：**群聊里只读不跑**，写/跑限私聊 |
| `harness_ask` / `harness_status` / `harness_reset` | 改代码 agent | 无 | ✅ 已 private-only；建议加「改动必须过 `verify_all` 才允许提交」 |
| `lore_add` | 写世界书 | 无 | ✅ 但建议限 owner，避免群友诱导她写错设定 |

### 5.5 主动开口

| 工具 | 作用 | 与心情的关系 | 结论/建议 |
|---|---|---|---|
| `proactive.interject` / `proactive.private` | 主动插话/私聊 | **应该**由心情+好感驱动 | ⚠️ 与 `stay_silent` 要互斥：静音期间不允许主动开口（否则「安静」形同虚设） |

### 5.6 三个共性建议

1. **工具数收敛**：36 个 → 建议合并成 ~20 个（画图 5→1、媒体 6→1、原神 4→1），
   `RET_TOOLS_TOP=6` 才有意义；否则「相关性检索」经常把名额浪费在同族工具上。
2. **工具结果不进心情**：任何工具返回（搜索结果、画图、视频）都只能进 THINK/记忆，
   **不能直接改 v/好感**——和 ADR-038 同一条原则。
3. **副作用工具要 owner**：写文件、跑代码、群管理、写世界书，群里一律只读或直接不挂。
