> 高好感难涨也难跌、低好感（讨厌）也黏、长期不联系只掉一点但不会归零、
> 负面事件比正面事件更重。

## 0. 先澄清两个数：0.15 是「事件上限」，不是「衰减」

| 名字 | 现在是多少 | 含义 |
|---|---|---|
| `REL_DAILY_CAP` | **0.15 / 天** | 一天内**同方向事件**累计最多改 0.15（防刷分） |
| `REL_AFFINITY_HALF_LIFE_DAYS` | **7 天**（再乘深度系数 0.1~4.5） | 时间衰减：每过一个半衰期，好感**乘 0.5** |

真正让「好感掉得快」的是第二个：**指数衰减到 0**。

### 现状算一遍（`scripts/simulate_affinity.py` 的 v1 列）

| 人设 | 当前好感 | 1 周 | 1 月 | 3 月 |
|---|---|---|---|---|
| 新认识 | 0.15 | −0.06 | −0.14 | −0.15 |
| 普通群友 | 0.30 | −0.10 | −0.24 | −0.30 |
| 好朋友 | 0.75 | −0.11 | **−0.37** | **−0.65** |
| 挚友 | 0.90 | −0.13 | **−0.44** | **−0.78** |
| 讨厌的人 | −0.60 | +0.20 | **+0.49** | +0.60 |

两个明显不对：
1. 好朋友一个月不聊天掉 0.37、三个月掉 0.65 —— 现实中不会；
2. 讨厌的人一个月就「不讨厌了」（+0.49）—— 怨恨没有这么容易消。

## 1. 参考了什么（理论 → 我们怎么用）

| 理论 / 研究 | 结论 | 落到模型上 |
|---|---|---|
| Ebbinghaus (1885) 遗忘曲线 | 遗忘先快后慢；无意义音节 1 个月只剩约 21% | 衰减要**前快后慢**，但不能像指数那样一路归零 |
| Wixted & Ebbesen (1991) *On the form of forgetting* | **幂函数**比指数函数更好地拟合遗忘数据 | 用 `(1 + t/T)^(-p)`，不用 `0.5^(t/τ)` |
| Anderson & Schooler (1991) / ACT-R | 幂律反映环境里「需要它的概率」；ACT-R 里 `d≈0.5` | 取 `p = 0.5` 作为默认 |
| Roberts & Dunbar (2011) 18 个月关系追踪 | 不联系 → 亲密感下降，但**关系有维持成本与层级**，不会一键清零 | 引入**不衰减的 bond 分量**（由投入决定） |
| Dunbar 分层网络（5/15/50/150） | 强关系数量有限，越靠内层越稳定 | bond 上限按「投入 I」分层 |
| Rusbult (1983) 投资模型 | 承诺 = 满意 + **投入** − 替代选项；投入越多越不容易散 | 投入 I 决定 bond 占比与衰减速度 |
| Baumeister et al. (2001) *Bad is stronger than good* | 负面信息权重更大、更难消除 | 负面事件权重 `NEG_BIAS≈1.7` |
| Gottman & Levenson (1992) | 稳定关系里正负互动比约 **5:1** | 同上：负向要更重，但正向可以持续累积 |
| Altman & Taylor (1973) 社会渗透理论 | 关系有「广度」和「深度」两层 | 两分量：`heat`（近期热度，会退）+ `bond`（深度，不退） |
| Ortony/Clore/Collins (1988) OCC | 情绪由「事件/行为/对象」评价产生 | 沿用现有 `impact` → 好感步长映射 |
| Park et al. (2023) Generative Agents | 工程上常用 `0.995/小时` 指数衰减做 recency | 只作为工程基线；关系比「记忆条目」更黏，故不用它 |

> 这些是**设计启发**，不是精确拟合：我们没有人际关系的时间序列真值，
> 参数按「可解释 + 可调 + 和用户直觉对齐」来定。

## 2. 模型结构

```mermaid
flowchart LR
  E[一次互动<br/>impact -2..+2] -->|Δ 事件步长| A[好感 a ∈ [-1,1]]
  A -->|拆成两分量| B[bond 底子<br/>不随时间衰减]
  A -->|拆成两分量| H[heat 热度<br/>幂律衰减]
  T[时间流逝 t 天] -->|只作用于 heat| H
  H -->|合成| A2[新的 a]
  B --> A2
  G[grudge 怨气] -->|放大负向 / 拖慢恢复| A
  I[投入 I<br/>记录数/认识天数/近期互动] -->|决定 bond 上限| B
  I -->|决定衰减时间常数| H
```

### 2.1 状态

- `a ∈ [-1, 1]`：显式好恶（现有 `profiles.affinity`）。
- `I ∈ [0, 1]`：投入，由**原始数据**算，不依赖好感（避免循环）：
  ```
  I = 0.5·min(1, 记录条数/20) + 0.3·min(1, 认识天数/120) + 0.2·min(1, 近7天消息/150)
  ```
- `g ∈ [0, 1]`：怨气（已有 `grudge`，14 天半衰期）。

### 2.2 时间衰减（幂律 + 底子）

对 `a ≥ 0`：

```
bond = a · β(I),   β(I) = 0.60 · I^1.5
heat = a − bond
a(t) = bond + heat · (1 + t / 10)^(-0.5)          # t = 距上次互动的天数
```

对 `a < 0`（讨厌不会自己变喜欢）：

```
a(t) = a · (1 + t / (30 · (1 + 2g)))^(-0.5)
```

要点：
- **bond 不衰减**：老朋友、老仇人都有「底子」；
- **heat 用幂律**：先快后慢，`t=10 天` 掉 29%，`t=30 天` 掉 50%，`t=1 年` 掉 84%（但只作用于 heat）；
- **负好感向 0 淡**，不会穿越到正；怨气 `g` 越大，淡得越慢。

### 2.3 事件步长（心情 → 好感）

判读给的 `impact ∈ {-2,-1,0,1,2}` 先映射成基础步长：

```
STEP = {1: 0.045, 2: 0.090}
```

再乘三件事：

```
正向： Δ = STEP[k] · conf · novelty · (1 − |a|)^0.70 · (1 − 0.5g)
负向： Δ = −STEP[k] · conf · novelty · (1 − |a|)^0.35 · 1.7
```

- `(1 − |a|)`：**两头饱和** —— a 越接近 ±1，越难推动（用户要的「越高越难增、越低也越难」）；
- 正向指数 0.70 比负向 0.35 更狠：**高好感时夸她，涨得更慢**；但被伤时还能真掉（`1.7` 倍权重）；
- `conf`：判读置信度；`novelty`：同一个人 30 分钟内重复同类事件递减（现有逻辑）；
- `g`：怨气越大，正向越难补（`1−0.5g`），负向越容易叠加（grudge 更新逻辑不变）。

硬护栏：单次 `|Δ| ≤ 0.20`，每日同向净变化 `≤ 0.15`（沿用 `REL_DAILY_CAP`）。

## 4. 数值对照（`python3 scripts/simulate_affinity.py` 实跑）

### 4.1 时间衰减：v1 → v2

| 人设 | 当前 a | 1 月 v1 | 1 月 v2 | 3 月 v1 | 3 月 v2 | 1 年 v2 |
|---|---|---|---|---|---|---|
| 新认识 | 0.15 | −0.14 | **−0.07** | −0.15 | −0.10 | 0.03 |
| 普通群友 | 0.30 | −0.24 | **−0.13** | −0.30 | −0.18 | 0.08 |
| 好朋友 | 0.75 | −0.37 | **−0.17** | −0.65 | −0.24 | 0.46 |
| 挚友 | 0.90 | −0.44 | **−0.18** | −0.78 | −0.25 | 0.60 |
| 讨厌的人 | −0.60 | +0.49 | **+0.18** | +0.60 | +0.30 | −0.17 |

- 「好朋友一个月掉 0.2 左右」→ v2 是 **−0.17**，符合直觉；
- 「越高越难降」：挚友 1 个月**相对**只掉 20%，普通群友掉 43%，新认识掉 47%；
- 绝对值上挚友（−0.18）仍略大于好朋友（−0.17）—— 因为起点更高、可掉的空间更大。
  **严格「绝对跌幅也随 a 单调下降」在数学上做不到**（否则高好感永远冻结），
  我们能保证的是：相对跌幅更小 + 长期下限更高 + 单次事件更推不动。

## 5. 实现要点（接线时必须注意）

### 5.1 幂律**不能**增量叠加

指数衰减是「无记忆」的，所以现在的 `decay_affinity()` 每次读都把 `affinity_at = now`、
把结果写回 `affinity`，反复调用结果一致。

幂律不是无记忆的：`f(7天)` 再 `f(23天)` ≠ `f(30天)`。
所以 v2 必须存**基准值 + 基准时间**：

```python
p["aff_base"] = a_now        # 上次事件之后的好感
p["aff_base_at"] = now       # 上次事件的时间（不是上次衰减的时间）
# 读：a(t) = decay(p["aff_base"], now - p["aff_base_at"])
# 写事件：先 a_now = decay(base, now-base_at)，再 a_new = a_now + Δ，
#         然后 base = a_new, base_at = now
```

`decay_affinity()` 改成**只读计算、不落盘**（或只在差异 >0.005 时落盘 base）。
否则每次状态卡渲染都会把 `aff_base_at` 推到现在，衰减永远不生效。

### 5.2 迁移（不跳变）

第一次以 v2 读某个人时：

```python
if "aff_base" not in p:
    p["aff_base"] = p.get("affinity") or 0.0
    p["aff_base_at"] = p.get("affinity_at") or now
```

之后只按新公式前进，**不回算历史**。已有 `affinity` 不变，用户不会看到二次跳变。

### 5.3 和 `intimacy` 的分工不变

- `affinity` = 喜不喜欢（事件驱动，本文档）；
- `intimacy` = 熟不熟（相处量派生，30 天半衰期）；
- v2 的 `I` 用**原始数据**（记录数/天数/消息数），**不用 intimacy**，避免循环依赖。

| `services/profiles.py` | `bump_affinity` / `decay_affinity` 走 v2；新增 `aff_base` / `aff_base_at` 字段 |

## 6. 验收清单（接线时写进 `test_new_features.py`）

1. 挚友 a=0.9 空窗 30 天 → 跌幅在 **−0.15 ~ −0.22**；空窗 365 天 → 仍 ≥ 0.55；
2. 普通群友 a=0.3 空窗 30 天 → 跌幅 ≤ 0.15；空窗 1 年 → ≤ 0.10；
3. 讨厌的人 a=−0.6 空窗 30 天 → 回升 ≤ 0.22，且**不会变正**；
4. 同一事件在 a=0.9 时的正向步长 < 在 a=0.3 时的 1/3；
5. 同一事件在 a=−0.9 时的负向步长 < 在 a=0 时的 1/2；
6. 负面事件步长 ≥ 同强度正面事件的 1.3 倍；
7. 反复调用 `decay_affinity` 不改变结果（幂律基准时间不被推动）；
8. 切换 `AFF_MODEL=v2` 后，旧档案第一次读取不产生 >0.02 的跳变。
