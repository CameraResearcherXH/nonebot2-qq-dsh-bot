# Harness 托管方案：定位与成本档位

> 版本：v2.0（2026-11-12）
> v1.0 的两个错误假设已作废：①「自建 agent loop」②「我们自己用这套系统」
> 正确前提：**本工程发布给 GitHub 用户，harness 接入是他们可选的加速手段，我们自己不运行**

---

## 0. 定位重述

| | v1.0（错） | v2.0（对） |
|---|---|---|
| 谁用 | 我们自己 | **clone 本工程的用户** |
| 做什么 | 自建 agent loop + 7 个插件 | **让工程「可被托管」+ 提供可选工具包** |
| 交付物 | 运行时框架 | 文档 + 配置 + 薄 MCP + 成本档位表 |
| 我们的维护负担 | 高（要跟 dsh 版本） | **接近零** |

### 0.1 最重要的设计原则

> **我们自己不用 → 任何需要长期维护的东西都不做。**

推论（三条硬约束）：

1. **不写 TS 插件。** dsh 是 v0.x，插件 API 会变，我们不用的东西没法跟版本。
2. **不维护 IDE。** 自建编辑器是无底洞，直接用 dsh-desktop / VS Code。
3. **所有接入物必须「可选、零依赖、不影响主流程」。** 用户不装 harness，`docker compose up` 照样能跑。

---

## 1. 关键发现：工程当前「不可托管」

用户想要的是「把工程直接丢进 DeepSeek Harness 全托管」。但检查后发现，**现在丢进去也托管不了**——不是 dsh 的问题，是工程对外资产缺失：

| 缺失 | 后果 | 优先级 |
|---|---|---|
| **没有 README.md** | 人和 AI 都不知道这项目是什么、怎么跑 | P0 |
| **没有 .env.example** | 只有 `.env`（含真实 key），用户不知道该配哪些项 | P0 |
| **没有 AGENTS.md** | dsh / Claude Code / Cursor 进来后无项目约定可依 | P0 |
| 根目录散落 `3a_zh.txt` `d3.txt` `e1.txt` `v1.txt` `jy.tex` `t_*.txt` | 噪音，AI 会去读这些调参笔记并误判 | P1 |
| `bot.py.working`、`test.py` 混在根目录 | 同上 | P1 |
| 没有目录职责说明 | AI 改错层（比如往 `plugins/` 里塞本该在 `services/` 的逻辑） | P1 |

**这些跟 dsh 无关，是任何 AI 工具（dsh / Claude Code / Cursor / Copilot）能用本工程的前提。**

换句话说：**P0 不是「接 harness」，是「把工程写到能被人和 AI 读懂」。**

## 2. dsh 能给用户什么（事实）

| 项 | 值 |
|---|---|
| 开源 | 2026-08-13，v0.1 开发者预览，MIT |
| 仓库 | `github.com/deepseek-ai/DeepSeek-Harness`，TypeScript |
| 规模 | 279,353 stars / 34,386 插件（2026-11-11） |
| 底座 | Cordis，「一切皆插件」，连 Agent Loop 和沙箱都可替换 |
| 模型 | 无关，近 40 家 provider |
| 预设 | 标准 / PTC / 极简 / 创造 |
| 多模态 | 已适配 `deepseek-v4-flash-vision-exp`（384 token/图） |

对用户的含义：**他们装个 dsh，把本工程目录打开，就能让 AI 帮着部署/排障/改配置——我们不用写一行插件。**

我们唯一要做的是：**让 AI 一进来就懂这个工程**。这就是 `AGENTS.md`。

## 3. 成本档位表（用户要的「成本集合」）

Flash 系列现价（2026-09-10 起，空闲/高峰翻倍）：

| 项 | 空闲 | 高峰 |
|---|---|---|
| 输入·缓存命中 | 0.02 元/M | 0.04 元/M |
| 输入·缓存未命中 | 1 元/M | 2 元/M |
| 输出 | 4 元/M | 8 元/M |

### 档位

| 档 | 组合 | 单任务成本 | 能力 | 适合谁 |
|---|---|---|---|---|
| **档 0** | 纯本地 Ollama（qwen2.5-coder 7B/14B） | **0 元** | 弱：长任务容易跑偏，工具调用不稳 | 完全不想花钱、只做小改动 |
| **档 1（推荐）** | dsh + V4-Flash | **约 0.2 元** | 够用：缓存命中 90~99%，30 步任务能跑完 | 绝大多数用户 |
| 档 2 | dsh + V4-Pro | 5~20 元 | 强：复杂重构、跨文件推理 | 深度改代码 |
| 档 3 | 混合路由（Flash 主力 + Pro 升级） | 0.2~2 元 | 平衡 | 进阶用户 |

### 关键成本事实（反直觉，必须写进文档给用户看）

- **长任务比短任务便宜。** 缓存命中 99% 时，30 步任务约 0.2 元；而频繁打断、每次改一行，缓存建不起来，单价按未命中 1 元/M 算，**相对贵 50 倍**。
- **所以：攒着一次说完，别一句一句喂。**
- 图片几乎免费：1000 张图 ≈ 38 万 token ≈ 0.04~0.38 元。
- 本地确定性计算（OCR / 文档解析 / embedding / 编译）**成本 0**，不要上云。

### 缓存三铁律（写进 AGENTS.md，让 AI 自己遵守）

1. 前缀稳定：system prompt、工具定义、项目背景放最前，**不插时间戳/随机 id**
2. 动态内容后置
3. 工具定义顺序固定

## 4. 我们提供的三层资产（全部可选）

### L0：工程可读化（必须做，与 harness 无关）

| 文件 | 内容 | 工作量 |
|---|---|---|
| `README.md` | 是什么、架构图、5 分钟跑起来、常见问题 | 中 |
| `AGENTS.md` | 给 AI 看的项目约定：目录职责、禁改项、启动步骤、排障入口 | 中 |
| `.env.example` | 全部配置项 + 注释（从现有 `.env` 抽，key 留空） | 中 |
| `docs/ARCHITECTURE.md` | 四层结构：`bot.py` / `plugins/` / `services/` / `data/` 各自职责 | 小 |
| 根目录清理 | 散落 txt 归到 `docs/notes/`，`bot.py.working` 删或进 `.gitignore` | 小 |

**这是本方案的核心交付，也是唯一必须做的部分。**

### L1：MCP 工具包（可选，Python，零运行时依赖）

把我们已有的能力暴露成标准 MCP Server，**任何 harness 都能挂**（dsh / Claude Code / Cursor）。纯 stdio 协议，几十行一个。

| MCP Server | 暴露什么 | 复用现有代码 |
|---|---|---|
| `qqbot-env` | 环境体检：`.env` 项是否齐全、依赖装没装、端口占用、docker 状态 | `plugins/selfcheck` |
| `qqbot-logs` | 容器日志 tail + 关键词过滤 + 常见错误识别（NapCat 未连、key 失效、端口冲突） | `docker logs` |
| `qqbot-config` | `.env` 每项的含义与建议值（把现有注释抽成结构化数据） | `.env` 注释 |
| `qqbot-deploy` | `docker compose up/down/restart`（危险，需审批） | `docker-compose.yml` |

**为什么值得做**：新人 90% 卡在「环境配不对 + 看不懂日志」。这 4 个工具直接把这段路铺平。

**为什么成本低**：全部是 `subprocess` + 读文件，不碰 dsh 内部，不跟版本。

### L2：简略 IDE（可选，建议不自己写）

| 选项 | 开发量 | 建议 |
|---|---|---|
| dsh-desktop（官方） | 0 | **首选**，直接推荐给用户 |
| VS Code / Cursor 打开目录 | 0 | 次选，改配置够用 |
| 项目自带单文件 Web 面板 | 300 行 | 仅当用户明确要「不想装任何东西」时做：`.env` 表单 + 日志流 + 部署按钮 |

**建议：L2 只写文档推荐，不自研面板。** 自研面板要跟着 `.env` 项变化同步维护，是无底洞。

## 5. 交付路线

| 期 | 内容 | 产出 | 工时 |
|---|---|---|---|
| **P0** | 工程可读化 | `README.md` + `AGENTS.md` + `.env.example` + `docs/ARCHITECTURE.md` + 根目录清理 | 1 天 |
| **P1** | 托管指南 | `docs/HOSTING_WITH_DSH.md`：装 dsh → 打开目录 → 说「帮我部署」→ 用 MCP 排障 | 半天 |
| **P2** | MCP 工具包 | `mcp/` 下 4 个 Python stdio server + 各 harness 挂载配置示例 | 1 天 |
| **P3** | 成本档位页 | `docs/COST_TIERS.md`：档 0~3 对比表 + 省钱实操建议 | 半天 |
| P4 | 简略 IDE | 仅按需，单文件 Web 面板 | 视需求 |

**P0 完成前，P1~P4 都没有意义**——AI 进来读不懂工程，给再多工具也白搭。

## 6. 风险

| 风险 | 对策 |
|---|---|
| dsh v0.x API 会变 | 我们只写 `AGENTS.md` + MCP，不写 TS 插件，天然免疫 |
| `.env.example` 泄露真实 key | 从 `.env` 抽取时逐项检查，key 一律留空 + 注释说明去哪申请 |
| MCP 工具包增加用户理解负担 | 全部标为可选，README 里放最后，不装不影响主流程 |
| AGENTS.md 写得太细反而束缚 AI | 只写「目录职责 + 禁区 + 启动步骤 + 排障入口」，不写实现细节 |
| 用户用档 0 本地模型跑崩，怪工程 | 档位表里明确标注档 0 的能力边界 |

---

## 7. 一句话总结

> **我们的活儿不是搭 harness，是把工程写到「任何 AI 都能接手」的程度。**
> `AGENTS.md` + `.env.example` + `README.md` 是 P0，MCP 是锦上添花，IDE 不用自己做。
