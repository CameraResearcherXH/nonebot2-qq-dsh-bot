# 能不能让「她」收发 QQ 红包？（可行性结论）

> 结论先说：**发红包做不到；收红包需要装 NapCat 原生插件，不是改 bot 代码就行。**
> 我们**没有**为此加任何自动抢/发逻辑（涉及真实资金 + 平台风控，必须先拍板）。

## 1. 查证过程（2026-11-26）

| 查什么 | 结果 |
|---|---|
| NapCat 主 bundle（`/app/napcat/napcat.mjs`）里的 `send_group_*` action | 只有 `send_group_msg / send_group_forward_msg / send_group_notice / send_group_sign / send_group_ark_share / send_group_ai_record` |
| 全包搜 `red_packet` / `hongbao` | 只有表情名（`hongbaobao` 等），**没有任何 action** |
| OneBot v11 标准 | 没有红包相关 action |
| 社区实现 | 抢红包靠 NapCat **原生插件**（如 `napcat-plugin-grabredbag`），在 QQ 客户端进程内 hook；不属于 OneBot 接口 |

所以：
- **收（抢）**：不是「调一个 API」能完成的。必须装 NapCat 插件，且插件要暴露一个 bot 能读写的开关（文件/HTTP），
  才能实现「只有主人说了才收」。
- **发**：需要 QQ 钱包支付能力，OneBot/NapCat 都没有暴露；只能做客户端 UI 自动化（极易风控/封号），**不建议**。

## 2. 如果一定要做，最小可行方案（只做「收」）

```text
QQ 群红包消息
   │
   ▼
NapCat 插件（grabredbag 之类）
   │ ① 读 /data/redpacket_allow.json（bot 写的授权文件）
   │ ② 命中白名单（群号 / 金额上限 / 主人 QQ）才抢
   ▼
抢到后写 /data/redpacket_log.jsonl
   │
   ▼
bot 的 owner 命令写授权文件 + 读日志回执
```

需要额外做的事：
1. 审核并固定插件版本（第三方代码跑在 QQ 进程里，权限等同你的号）；
2. 给插件加**授权文件**读取（默认关闭）——这一步必须改插件，不是我们的仓库；
3. bot 侧加 owner-only 命令（`/红包 收 开|关`、`/红包 上限 5`），写授权文件；
4. 单群开关 + 金额上限 + 每日次数上限，避免「被拉进薅羊毛群」。

## 3. 风险

- **平台规则**：自动抢红包属于自动化交易行为，可能触发风控（限流、冻结、封号）；
- **资金**：发红包是真实支付，出错无法回滚；
- **第三方插件**：能读到你的登录态，等于把号交给它。

## 4. 建议

- **短期**：不做自动收发。她可以正常聊红包话题（「发啥红包，先请我吃白饭」），但不实际领取。
- **中期**：如果确实要，先只做「收」+ owner 授权 + 单群白名单 + 金额上限，并在群里明确告知。
- **不做**：自动发红包。
