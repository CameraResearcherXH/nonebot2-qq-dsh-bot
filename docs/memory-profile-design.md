# 记忆 · 档案 · 心情 · 好感：as-built 详解

> 心情 / 好感的数值模型见 [mood-affinity-design.md](archive/mood-affinity-design.md)；
> 这一篇讲**数据怎么落、怎么读、怎么进 prompt**，以及为什么这么设计。

## 1. 四层数据，各管什么

| 层 | 回答的问题 | 存储 | 生命周期 |
|---|---|---|---|
| **对话流水** `data/dialogue/*.jsonl` | 当时到底说了什么 | 一天一个 jsonl | 默认 14 天 |
| **记忆** `memory_v2` / `memdb` | 哪些事值得记住、什么时候能想起来 | json / sqlite | 长期（按显著性衰减） |
| **档案** `data/profiles/*.json` | 这个人是谁、怎么称呼、关系底色 | 一人一档 | 长期 |
| **心情 / 好感** | 她现在的状态、对某个人的慢变量 | `mood.json` / profile | 现在进行时 / 慢变量 |

关键原则：**流水是唯一权威源**。记忆、现场、档案都可以从流水重建；
反过来不行（档案里没有原话）。

## 2. 对话流水

写入点：`plugins/chat` 的 priority=1 观察器（`_early_observe`）和发送层。

```json
{"ts": 1790000000.0, "gid": "123456789", "who": "阿明(1234)",
 "qq": "10001", "kind": "user", "text": "今天好累", "to": "10002"}
```

- `kind`：`user` / `bot` / `peer`（另一只 bot）；
- **她自己的话**用 `kind:"bot"`，`qq` 写**人格 ID**（见下）；
- 图片会落 `data/images/`，记录里带 `img` 和 `vision`（识别结果）；
- 默认保留 14 天（`DIALOGUE_KEEP_DAYS`），避免磁盘无限增长。

### 2.1 人格 ID：换号不丢记忆

`services/identity.py` 维护一个**和登录 QQ 解耦的人格 ID**：

- `SELF_ID`（`.env`）是「她是谁」，**换号时不要改**；
- `NAPCAT_ACCOUNT` 是「现在登录的号」，换号只改这个；
- `SELF_ALIASES` 列出以前登录过的号；
- 判「这是不是她自己」用 `identity.is_self(qq)`，**不要写 `qq == event.self_id`**；
- 写日志 / 判收件人 / 白月光统计，统一用 `identity.canonical()`。

这样 100000018 被冻结、换 100000010 之后，旧号说过的话、别人 @ 旧号的记录
仍然算「她」，不会被当成陌生群友。

## 3. 记忆

### 3.1 写入：三个来源

| 来源 | 触发 | 内容 |
|---|---|---|
| 她自己的 `[[MEMO|...]]` | 真的被触动 / 值得记的相处经历 | emotion + think + text |
| 系统补记 | 判读 \|Δ\| 超过阈值但她没写 | 事件 + 当时心情 |
| 显式 `[[REMEMBER|...]]` / `/记住` | 用户要求 | fact |

一条记忆的结构（json 后端）：

```json
{"id": "...", "ts": 1790000000.0, "kind": "event|bond|fact|impression",
 "summary": "他半夜陪我改代码到三点", "detail": "完整原文/心理活动",
 "about_qq": "10001", "gid": "123456789", "importance": 0.8,
 "salience": 0.9, "valence": 0.6, "mood_word": "被戳到",
 "tags": ["代码", "陪伴"], "access": 0, "last_access": 0}
```

### 3.2 为什么用「显著性」而不是「记不记」

早期设计是「心情波动大才记」，结果：

- 平淡但重要的约定（「下次换个大碗再发给我」）永远记不住；
- 同一个人反复出现的小事全丢，档案里只剩标签。

现在改成 **Δ 不决定记不记，只决定加不加粗 / 好不好查**：

- 记录由「她写了 MEMO / 系统阈值 / fact」决定；
- `salience` 决定召回排序（`w_emo = 1 + 2.5 * salience`）；
- 时间衰减 `w_forget = exp(-days / τ)`，但 `kind=bond` 衰减更慢。

### 3.3 读：目录 → 详情

模型不会一次看到全部记忆，而是两级：

1. `recall_catalog(query, offset, limit)` 给目录（摘要 + 时间 + 标签）；
2. 模型想看细节，再 `recall_detail(id)` 展开原文。

prompt 里只放**和当前说话人 / 当前话题相关**的几条（默认 4 条），
避免「记忆把 prompt 撑爆」。

### 3.4 群隔离

`gid` 字段让「群内记忆只在群内用」：
同一个人的私聊记忆不会在群里被念出来（除非是 `kind=fact` 的长期事实）。

## 4. 档案

`data/profiles/<qq>_profile.json` + `<qq>_style.json`：

| 字段 | 含义 | 谁写 |
|---|---|---|
| `nickname` / `aliases` | 群名片 / 别名 | 观察器 |
| `call_name` | **她怎么叫这个人** | `[[CALL|user:...]]` / `/改名` |
| `bot_alias` | **这个人怎么叫她**（专属唤醒词） | `[[CALL|bot:...]]` |
| `role` / `identity` / `note` | 身份、备注 | 档案挖掘 |
| `groups.<gid>` | 群内称呼 / 角色 / 是否静音 | 群内观察 |
| `bond_word` | 好感名词 | 好感更新 |
| `bond_notes` | 相处经历（**只收 |Δ|≥0.15 的大波动**，带情绪权重） | 判读回流 |
| `affinity` | 好感数值 | 判读 Δ |

### 4.0 档案只收「大波动」的事（2026-11-25）

档案和记忆的职责必须分开，否则两块的重复率会很高：

| | 记什么 | 密度 |
|---|---|---|
| **记忆** | 发生了什么（细节、可检索、每 turn 都记） | 密 |
| **档案** | **让她心情明显动过**的事（1 条「印象最深」+ 少量事件） | 稀 |

规则：

- 门槛 `PROFILE_NOTE_MIN_DELTA=0.15`（`core/tuning.py`）：判读的 `|Δ|` 低于它，
  `profiles.add_bond_note` 直接丢弃，只留在记忆里；
- **事实类不进档案**：`/记住` 的事实、看过的 B 站视频、普通闲聊，只进记忆；
- `profile_miner` 只写**带明确情绪**的事件，`neutral` 一律跳过；
- 回复前「档案」块**不再调 `memory_v2.recall`** 取「印象最深的事」，
  改读 `bond_notes` 里 `|Δ|` 最大的那条——档案和记忆不再各查一遍同一件事。

### 4.1 称呼是双向的

- `call_name`：她叫对方什么（「你叫我阿明吧」）；
- `bot_alias`：对方叫她什么（「我可以叫你小鲸鱼吗」）→ 以后这个人喊这个名字 = @ 她；
- **默认没有全局称呼响应**：`ME_COMMON_NAMES` 为空，只认人格名 + 每个人的 `bot_alias`；
- 两个字段都挂在**对方**的档案上，所以换号不会丢。

### 4.2 档案怎么挖

`services/profile_miner.py`：

- 每攒够 N 条发言（默认 12）在后台提炼一次；
- 读最近 400 条流水，让模型输出「简介 / 性格 / 事情」；
- 她自己（任何登录号）**永远不建档案**；
- 失败静默，不影响聊天。

## 5. 心情 / 好感（只讲接线）

数值模型见 [mood-affinity-design.md](archive/mood-affinity-design.md)，这里只讲数据怎么流：

```
一轮对话
  ├─ 她写 [[THINK|…]] / [[MOOD|…]] / [[MEMO|…]]
  ├─ 判读模型（deepseek-chat）读「这一轮 + 最近 8 条」→ Δ / 好感对象 / 收件人
  ├─ mood.apply_delta(Δ)            → data/mood.json
  ├─ profiles.bump_affinity(Δ, 对象) → 对方档案
  └─ memory_v2.remember(...)         → 记忆
```

三个关键约束：

1. **一个 Δ，三处用**：记忆刻痕、好感、心情，但用途不同（记忆是加粗，好感是慢变量，心情是现值）；
2. **环境 vs 人**：只有「某个人导致的变化」才进好感；群氛围只进群心情；
3. **每日净变化上限**：防止「持续跌」一天到底（`AFFINITY_DAILY_CAP`）。

## 6. 进 prompt 的顺序

固定区（吃缓存）→ 动态区（每轮变）：

```
角色卡
规矩（▍00~▍13，编号小的优先）
人称与指代
【历史对话】（带收发件人）
【群聊现场】（线程 / 谁在叫 / 上一句）
【相关记忆】（4 条以内）
▍这个人的档案
▍你对他的底色（好感 + 印象最深的一件事）
▍现在的状态（心情 + 峰值事件）
▍白月光模式
【当前消息】
```

原则：**静态的放前面，动态的放后面**，否则每轮前缀缓存全失效。

## 7. 踩过的坑（都已修）

| 现象 | 根因 | 修法 |
|---|---|---|
| 好感「从来没进过 prompt」 | `build_packet` 产出了 `relation`，注入清单漏了 | 补进 `llm.py` 注入清单，并前移到动态区 |
| 重启后现场只剩最后一句 | 现场只在内存，重启即空 | `seed_from_log()` 从流水补最近 N 条 |
| 记忆「只有标签没有内容」 | `profile_miner` 写好了但没人调用 | 观察器里接上 `note_message` |
| 心情判读看到的是未处理原文 | 判读回退用了 `_db_history` | 统一走 `group_scene.history_lines` |
| 换号后旧号被当群友 | 身份判断用 `event.self_id` | `services/identity.py` 别名表 |
| 白月光统计把自己算进去 | `note_incoming` 只排当前号 | 任一别名都跳过 |
