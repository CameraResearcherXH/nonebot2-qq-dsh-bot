# 代码体检 / DSH 能力核对（2026-11-24）

> 这份是内部体检报告，`make_dist.py` 会排除 `docs/review-*.md`，不进发行仓。

## 一、我们的 DSH 桥 vs Aurabot

**结论：不等于 Aurabot，也不该等于。**

Aurabot（`dsh-aurabot-qq`）本身是 **DSH 的一个插件**：它自己接管 QQ（SnowLuma/OneBot），
自己实现人格/心情/记忆/表情/语音/空间/B站/桌宠/模块市场/权限页/面板。
它和本项目是**两条路线**，不是「我们少做了几个函数」的关系。

| 能力 | Aurabot（DSH 插件） | 本项目 | 说明 |
|---|---|---|---|
| QQ 接入 | 自己接管（SnowLuma） | NoneBot + NapCat | 我们不能和它同时接管同一个号 |
| 人格 / 心情 / 好感 | 有 | 有（更细：五层自我） | 我们的强项 |
| 长期记忆 | 有（3000 条默认） | 有（memory_v2 + 图书馆） | 我们的强项 |
| 表情 / 语音 / 唱歌 | 有（模块） | 有（sticker/song_cover） | 需要算力机 |
| QQ 空间 / B 站 / 桌宠 | 有（模块） | 部分（B 站预览/视频理解） | 没有空间日记、没有桌宠 |
| 模块市场 / 面板 | 有 | 无（我们是代码级插件） | 设计取向不同 |
| 权限页 / 试运行 | 有 | 部分（is_owner + skill_switch） | 没有逐操作权限矩阵 |
| **DSH 会话** | 原生（每个会话一个 DSH） | 只有「改代码」一条桥 | 见下 |

我们的桥（`services/harness.py` + `plugins/harness`）只做一件事：
**QQ（主人）→ 一条需求 → DSH 跑完 → 结果原样回 QQ**，带人格/心情/好感/白月光/记忆做背景。

它**没有**：DSH 面板、模块热插拔、空间/B站/桌宠、权限页、试运行、多会话可视化。

⚠️ **核实结果：服务器和本地都没有装 `dsh`（`which dsh` 为空）**，
所以这条桥目前只做了「协议层」验证（单测里用假命令跑通 cli 后端），
没有和真实 DSH 联调过。要用必须先在本机装 DSH 并填 `HARNESS_CLI` 或 `HARNESS_URL`。

## 三、确认「不是 bug」的地方（免得以后重复排查）

- `_enrich_text` 有 4 个调用点，但结果缓存在 `event._enriched_text`，实际只跑一次。
- `recall_hits` 只跑一次：`llm.py` 拿到 `_hits` 后两次 `build_packet` 都复用（`hits=_hits`），
  不会重复 BM25 / 重复写 index。
- `group_scene.observe` 每个消息只调一次（另外两处是 `ensure_seeded` 和指令分支）。
- `scene_auditor` 在 worker / 主动插话 / 翻历史三处调用，但 `needs_audit()` 会跳过
  @/引用/开头称呼 这些强信号，不会重复审。
- `REPLY_INTERVAL=6` 现在几乎不生效（被 `GROUP_REPLY_COOLDOWN=45s` 覆盖），
  两者都留着是为了私聊和「刚被 @ 完的连发」两种场景，不算矛盾。

## 五、设计上值得注意的两处

1. **省流模式 vs 关注期**：`GROUP_REPLY_COOLDOWN=45s` 会拦掉「关注期」的后续几句，
   如果希望被 @ 后还能追几句，把 cooldown 调到 15~20s，或给关注期单独放行。
2. **audit 的成本**：每次回复前一次审核 LLM 调用（`purpose=audit`，约 590 次/天）。
   省流模式下大多数消息根本不入队，audit 会自然下降；全量模式想省，可以把
   `SCENE_AUDIT_ENABLED=false`，代价是「谁 → 谁」只靠硬逻辑。
