# 两个「风格类」模块：表达学习（expression）与注意力漂移（attention）

> 这两个模块经常被问「到底在干什么」——它们**不产生内容、不改数值**，
> 只影响「这句话怎么说」。一个是**学别人怎么说话**，一个是**控制走神的程度**。

---

## 1. 表达学习 expression（`services/expression.py`）

### 1.1 它解决什么问题

人格卡是**全局固定**的：她在每个群、对每个人都用同一套腔调。
真人不是这样——在 A 群爱用短句吐槽，对某个熟人语气会软下来。

所以这个模块学的是**说话方式**（口癖、句式、语气词、爱怎么接话），
**不是知识**。知识归 lorebook（谁是谁、梗什么意思）。

### 1.2 数据怎么来

```
群里每攒够 EXPRESSION_EVERY=40 条真人消息（且距上次 >= EXPRESSION_MIN_INTERVAL=600s）
  → 后台 expression.mine(gid, 最近 30 条 [(名字, QQ, 文本)])
  → 一次模型调用，同时产出两类：
       group：这个群特有的说法
       persons：其中某个人特有的说法（最多 2 人）
  → 每条带 scene（吐槽/附和/敷衍/安慰/接梗/自嘲/催/夸/问）
        和 tone（短/冲/软/阴阳/正经），正文 ≤20 字
  → 落盘 data/expression/<scope>.json，同一条重复出现 → count+1
```

存储示例：

```json
{"items":[
  {"text":"你礼貌吗","scene":"吐槽","tone":"阴阳","count":3,"at":1795...},
  {"text":"先这样吧","scene":"敷衍","tone":"软","count":1,"at":1795...}
]}
```

作用域两种：`group_<gid>`、`person_<qq>`。

### 1.3 怎么用

- 回复前 `expression.render(gid, qq)`：
  - 从 group 里按 `(1+count)/(1+天数*0.5)` 加权随机抽 **1 条**；
  - 从 person 里同样抽 **1 条**；
  - 渲染成一段 `▍说话风格参考`，塞进 depth 区（离当前消息最近）；
  - 明确写「学他们的语气，不是知识；别照抄原句、别每句都用」。
- `/表现`：看她自己总结的「我在各处的样子」（`self_view()`）；
- `/表现 清`：全部忘掉。

### 1.4 设计上的几个要点

| 要点 | 原因 |
|---|---|
| 只抽 1+1 条，随机加权 | 固定注入会让她变成复读机；随机才像「潜移默化」 |
| 只学 ≤20 字的说法 | 长句会变成台词抄袭，短句才是口癖 |
| 排除「哈哈哈」这类通用词 | 否则学到的全是全网通用废话 |
| `render()` 不检查 enabled | 已经学到的数据是免费的，没 key 也该继续用 |
| 失败静默 | 挖不到不影响聊天 |

### 1.5 怎么验证它活着

```bash
# 有没有数据
ls data/expression/
cat data/expression/group_<gid>.json

# 日志里挖到新说法
docker logs qq-grok-bot | grep "\[EXPR\]"

# 真实 prompt 里有没有注入
/测函数 模板          # 找「说话风格参考」块
```

## 2. 注意力漂移 attention（`services/attention.py`）

### 2.1 它解决什么问题

我们给模型的约束几乎全是**负向**的：「只接一个线程」「别总结」「别替别人说话」。
模型被管得很老实，结果只有两种反应：正面回答，或者完全不接。
缺少真人那种「被一个细节勾走一下，然后拐回来」的活气。

这个模块把「走神」做成**可调的三个旋钮**，而不是靠模型随机发挥。

### 2.2 三个旋钮

| 变量 | 取值 | 含义 |
|---|---|---|
| `ATTENTION_DRIFT` | `subtle` / `active` / `scattered` / `wild` / `off` | 漂移强度：几乎不漂 → 可以明显发散 |
| `ATTENTION_ANCHOR` | `strict` / `balanced` / `loose` | 回钩策略：联想完多快回到正题 |
| `ATTENTION_REACTION` | `reserved` / `natural` / `lively` | 短反应风格：先来一句「啊？」再说的频率 |

默认 `active / balanced / natural`。

### 2.3 它输出的内容（会被塞进规矩块的 `02d 注意力风格`）

```
· 你可以被聊天里新鲜、好笑、反差强或熟悉的人/梗短暂吸引，
  但每次漂移都要能从最近消息里找到明确触发点。
· 漂移不是换话题：先抓住那个突出的点，再用很短的一句拐一下，然后回到正在聊的事。
· 每轮最多一次明显跳跃；别人明确在问你什么，就必须先答那个。
· 这是风格，不是毛病：不要自称分心、不要提 ADHD、不要说「我走神了」。
· 漂移档位：活跃。可以主动抓住新鲜、好笑、反差强或熟悉的细节接话……
· 回钩策略：自然。可以短暂沿着支线说一句，但结尾或主要意思要回到当前聊天。
· 短反应：自然。可以偶尔先用短句、吐槽或语气词接住话题，再继续正常回复。
```

### 2.4 关键设计：硬约束写死在每一档里

- 每次漂移必须能在最近消息里找到触发点（不能凭空联想）；
- 漂移 ≠ 换话题（先抓住，再拐回来）；
- 每轮最多一次明显跳跃；
- 不能无视明确提问；
- 不要自称分心 / 不提 ADHD（防止变成「人设表演」）。

这些是**风格约束**，不参与任何数值计算（不影响心情、好感、记忆）。

### 2.5 怎么调 / 怎么验证

```bash
# .env
ATTENTION_DRIFT=active
ATTENTION_ANCHOR=balanced
ATTENTION_REACTION=natural
```

```bash
/测函数 审核        # 会带 attention.status()，显示当前三档
/测函数 模板        # 找「02d 注意力风格」块，看实际文案
```

想让她「老实一点」：`ATTENTION_DRIFT=subtle` + `ATTENTION_ANCHOR=strict`；
想更跳脱：`scattered` + `loose`（但仍受「每轮一次」约束）。

## 3. 两个模块和「重复块」的关系（2026-11-22 去重）

它们各自只注入**一次**：

- `attention.render()` → 规矩块固定区 `02d`（`_behaviour_protocol` 里）；
- `expression.render()` → depth 区一段 `▍说话风格参考`（llm 文本/视觉两条分支各一处，
  但一次请求只会走其中一条）。

真正造成「模板重复」的不是它们，而是：

1. `build_packet` 的 micro 人物卡 + llm 的 brief 人物卡（同一个人描述两遍）
   → 现在有 brief 卡时不再塞 micro；
2. brief 卡自带 `▍名字（QQ…）` 标题，llm 又套了一层
   `▍这一条在跟你说话的人` → 现在直接用卡本身；
3. `/测函数 模板` 以前是**重新拼**一遍（packet + relation + mood 全打），
   必然和 packet 里的块重复 → 现在直接读 `llm._LAST_MSGS`（真实请求）。
